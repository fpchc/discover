# LLM 接入与流式解析规范

## 适用场景

- 新增或修改模型提供方、LLM 客户端、请求模型或流式解析
- 调整思考内容、工具调用分片、usage、超时与重试
- 排查模型流中断、字段兼容或工具参数拼接问题

## 不适用场景

- Agent 阶段编排、工具执行策略或 SSE 前端事件

## 职责边界与权威来源

本文件定义提供方无关的 LLM 接入契约。当前提供方、模型、地址和启用状态以配置注册表为准；代码路径以 `.ai/MODULE_MAP.md` 为准。

## 1. 接入原则

- 使用 OpenAI 兼容的 chat-completions 请求语义。
- 所有传输通过注入的 `httpx.AsyncClient`；禁止业务层自行创建客户端或引入另一套 HTTP / SDK 生命周期。
- Provider 差异封装在注册表、请求构造和流式解析边界，不泄漏到 Runtime。
- 模型 ID、base URL、密钥变量名、能力标志、上下文窗口、超时和重试全部配置化。

## 2. 提供方注册表

每个提供方结构化声明：

- 逻辑 ID 与展示名
- base URL、真实模型 ID、API key 环境变量名
- 是否支持 thinking、对应流式字段名
- 是否支持工具调用
- context window、timeout、retries

智能体只引用逻辑 ID 或 alias。密钥按需解析，不写入注册表、日志或进程级全局可变状态。

## 3. 客户端职责

LLM 客户端只负责：

1. 解析提供方与密钥；
2. 构造请求头和请求体；
3. 发起异步流式请求；
4. 把原始分片交给解析器；
5. 把网络、协议和上游错误转换为统一异常。

它不负责 Agent 循环、预算、工具执行、消息持久化和 SSE 编码。

## 4. 请求契约

- 请求、消息和工具规格使用 Pydantic 模型。
- `system / user / assistant / tool` 角色字段保持提供方兼容。
- tools 使用统一 function schema；无工具时不发送无意义的提供方扩展字段。
- thinking 只在调用方请求且提供方支持时启用。
- 采样参数由调用上下文显式给出，不在客户端散落默认值。

## 5. 流式分片语义

解析器把提供方原始分片归一为稳定语义事件：

- 正文增量
- 思考增量
- 工具调用增量
- 完成原因
- usage

Runtime 只消费归一结果，不读取提供方原始 JSON 结构。未知但无害字段忽略；关键结构缺失或非法时抛协议错误。

## 6. 思考内容

- thinking 字段名由提供方配置决定，不在解析器内按模型名分支。
- 思考与正文必须分别累计和输出，禁止混入最终 answer。
- 提供方不支持 thinking 时应确定性关闭，而不是尝试发送未知参数。
- 用户可见内容不得泄露内部系统提示、隐藏上下文或工具命名空间。

## 7. 工具调用分片

- 按调用 index / ID 聚合跨分片的名称和 arguments。
- arguments 拼接完成后再解析 JSON；流中间态不得提前判为非法。
- 多个并行调用分别维护缓冲区，最终顺序可追踪。
- 流结束仍无法形成合法调用时，返回可分类、可修复的协议错误，不执行残缺参数。

## 8. Usage 与缓存 token

统一记录 input、output、total，以及提供方可用时的 cached read / write。缺失字段按零处理，但不得伪造。usage 聚合属于独立组件，不能靠字符串解析正文推断。

## 9. 错误、重试与超时

- 区分鉴权、限流、超时、网络、协议和服务端错误。
- 只对明确可重试且幂等的失败按配置重试；认证和参数错误不重试。
- 每次重试必须受总预算和取消作用域约束，不得形成嵌套无限重试。
- 日志只记录必要元数据，禁止密钥、完整请求体和敏感响应。

## 10. 本规范专属检查

- [ ] 新提供方只通过注册表和适配边界接入
- [ ] Runtime 未读取提供方原始字段
- [ ] thinking、正文、工具调用和 usage 分离正确
- [ ] 工具参数在完整聚合后才解析执行
- [ ] 超时、重试、模型和密钥均配置化且日志已脱敏

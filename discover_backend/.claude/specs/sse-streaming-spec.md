# SSE 流式输出规范

## 适用场景

- 修改流式对话接口、RunEvent 到 SSE 帧映射、心跳或打字机节流
- 调整思考区、正文、工具、错误和终态事件
- 排查成块输出、断流、乱序、重复终态或代理缓冲

## 不适用场景

- LLM 原始分片解析、Agent 阶段编排或前端视觉样式

## 职责边界与权威来源

本文件定义稳定的流式传输行为。具体 DTO、事件类和代码路径以 `.ai/MODULE_MAP.md` 为准；接口示例以 `docs/` 中当前 API 文档为准。

## 1. 基本契约

- `response_mode=streaming` 使用 SSE；blocking 使用普通 JSON，二者共享同一业务执行结果。
- SSE 帧包含明确事件类型和 JSON data，不把内部 Python 对象直接序列化输出。
- 一个 Run 只允许一个终态；终态后不得继续发送正文、思考或工具事件。
- 连接关闭、客户端取消和执行终止必须向下传播并触发资源清理。

## 2. 事件分区

至少区分：

- 会话 / Run 建立
- 正文增量
- 思考开始、增量、结束
- 工具调用开始与结果
- 产物
- 降级与错误
- 心跳
- 完成或其他终态

思考内容不得混入正文 answer；工具内部结果不得冒充模型正文。前端只依赖公开帧契约，不感知 LangGraph、MCP 或脚本内部结构。

## 3. 顺序与幂等

- 内部事件必须具备单 Run 可排序标识；映射层保持因果顺序。
- 开始事件先于对应增量和结束事件。
- 工具结果必须关联原调用；并发完成可乱序，但关联关系不能丢失。
- 错误与完成互斥；重复终态在映射层丢弃或归一，不得对外发送两次。

## 4. 打字机节流

LLM 分片粒度不稳定，正文需要经过服务端节流缓冲再发送：

```text
模型正文分片 → 字符 / grapheme 缓冲 → 定时取出 → SSE 正文增量
```

- 只节流用户可见正文；工具、错误、产物和终态不为视觉效果延迟。
- 速率、批量大小和刷新间隔配置化。
- 上游结束后必须排空正文缓冲，再发送终态。
- 不为等待 Markdown 结构闭合而长期缓存正文。

## 5. Unicode 与格式

按 Unicode grapheme cluster 切分，避免拆开 emoji、组合字符和变体选择符。换行、Markdown、代码块和链接保持原始文本顺序；格式容错属于前端渲染职责，服务端不重写模型正文。

## 6. 心跳与代理

- 无业务数据期间按配置发送 `ping` 心跳，防止代理和浏览器判断连接空闲。
- 心跳不改变 Run 状态、不进入对话正文、不参与 token 统计。
- 部署层必须禁用响应缓冲并设置适合长连接的超时。
- 每个帧及时 flush，不等待大缓冲区累积。

## 7. 背压与队列

- 正文增量允许在保持顺序和文本完全等价的前提下合并。
- 工具、错误、产物、状态转换和终态不可丢弃或合并。
- 队列满时使用背压或受控正文合并，禁止静默丢事件。
- 慢客户端不得无限增长内存；达到配置限制时应取消 Run 或返回明确终态。

## 8. 脱敏与错误

所有帧在发送前统一脱敏和长度控制。禁止输出密钥、认证头、完整请求体、系统提示、内部路径、堆栈和内部智能体 ID。用户可恢复错误与不可恢复错误使用稳定公开错误码和简短建议。

## 9. 资源释放

异常、取消和正常结束都必须：

1. 停止节流与心跳任务；
2. 排空或明确放弃缓冲；
3. 结束事件源；
4. 释放工具、MCP、数据库和锁等生命周期资源；
5. 避免后台任务继续向已关闭连接写入。

并发任务统一由 anyio task group 管理。

## 10. 本规范专属检查

- [ ] 思考、正文、工具和终态帧互不混流
- [ ] 正文缓冲在终态前排空，且每个 Run 仅一个终态
- [ ] grapheme 切分、心跳、禁缓冲和 flush 行为正确
- [ ] 队列存在背压上限，关键事件不丢失
- [ ] 所有帧发送前已脱敏，取消路径已释放资源

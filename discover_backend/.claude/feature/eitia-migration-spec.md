# EITIA 智能体迁移指南

## 适用场景 / 何时触发

- 把 `eitia-client-finder` 从单技能包迁移为智能体包时
- 改造脚本中的绝对路径时
- 放宽门禁以适配 P1 数据受限场景时
- 验收迁移后的端到端流程时

---

## 1. 身份转换

| 维度 | 原形态 | 目标形态 |
|------|--------|---------|
| 定位 | 单技能包 | 智能体（下辖一个技能） |
| 目录位置 | `eitia-client-finder/` | `agents/discover/` |
| 清单结构 | 一个 `SKILL.md` | `AGENT.md` + `skills/client-finder/SKILL.md` |
| 七大类场景 | 曾考虑做成七个技能 | 合并为一个技能内的路由分支（工作流正文描述） |

**为什么七场景不拆成七技能**：它们共享八维评分逻辑、共享模板、共享去重机制，拆开会导致大量重复。场景判定写在技能工作流正文里，靠模型阅读后分支，而非靠平台路由。

---

## 2. 目录结构重组

```
agents/discover/
├── AGENT.md                          智能体清单
├── skills/
│   └── client-finder/                唯一技能（P1）
│       ├── SKILL.md                  技能清单 + 工作流正文
│       ├── references/               七篇参考文档保持不变
│       │   ├── scene-routing.md
│       │   ├── tier-funnel-prompts.md
│       │   ├── data-source-mapping.md
│       │   ├── scoring-rules.md
│       │   └── ...
│       ├── scripts/                  可执行脚本
│       │   ├── score_calculator.py
│       │   ├── dedup_manager.py
│       │   └── render_report.py
│       ├── schemas/                  脚本入参约束
│       │   └── score_input.json
│       └── templates/                报告模板
│           └── eitia-cfr.html
└── shared/                           智能体级共享（P1 用不到）
```

**templates 归技能而非平台**：报告模板是 EITIA 客户发现这个技能专属的，换智能体就不需要。

## 3. AGENT.md 内容

| 字段 | 填写 |
|------|------|
| 智能体 ID | `eitia` |
| 显示名称 | EITIA 电子信息产业链客户发现智能体 |
| 版本 | 继承原版本号，如 `1.4` |
| 一句话职责 | 为电子信息产业链销售寻找潜在客户，输出量化评分报告 |
| 适用边界 | 适用：寻找/开发/评估潜在客户、竞品反推、行业扫描、区域聚焦。不适用：已成交客户的售后、非电子信息产业链的通用销售 |
| 默认技能 | `client-finder` |
| 模型偏好 | `opus`（高推理要求） |
| 思考模式偏好 | 启用，强度中（需要规划多路并发搜索与评分） |
| 环境变量白名单 | `["ALIBABA_SEARCH_TOKEN"]`（P1 仅需搜索令牌） |
| 技能索引 | `["client-finder"]` |

正文写智能体全局约束：专业语气、输出格式、通用禁令、跨场景一致的纪律。控制在技能正文的三分之一以内。

## 5. 门禁放宽

P1 数据受限，原有的硬门禁会导致永远无法通过。需放宽为"尽力而为 + 标注"。

| 原门禁 | P1 放宽版 |
|--------|----------|
| 候选池 ≥ 15 家 | 候选池 ≥ 5 家（搜索覆盖面不如原企业数据库） |
| 每企业至少 5 个数据维度 | 每企业至少 2 个维度（搜索 + 推断） |
| 脉脉数据已采集 | 去除该门禁（P1 无脉脉） |
| 股权架构必填 | 改为"尽力采集，缺失时标注数据来源受限" |
| 竞品数据交叉验证 | 改为"至少一个来源，标注来源数量" |
| 上市状态交叉验证 | 改为"优先使用搜索确认，不得凭注册资本推断" |

阻断型门禁只保留**报告结构完整性**相关的（如"render 校验通过"），数据完整性相关的改为警告。

## 6. 脚本路径改造

扫描三个脚本，替换绝对路径。

| 脚本 | 原问题路径 | 改造 |
|------|-----------|------|
| `render_report.py` | `D:\ClaudeCode\Report\` | 改为 `Path(os.environ["SKILL_WORKSPACE"]) / "output"` |
| `deploy_pdf.py` | 同上，且 `cp` 到 Kami 目录 | P1 删除外部部署步骤，渲染直接在工作区完成 |
| `dedup_manager.py` | `.cache/recommendation-history.json` | 改为 `Path(os.environ["SKILL_WORKSPACE"]) / "data" / "history.json"` |

`deploy_pdf.py` 的外部部署是最大障碍——它把文件复制到 Kami 模板目录再构建 PDF。多会话下会互相覆盖。

**P1 简化方案**：去除 Kami 外部构建，改为直接在工作区内用 WeasyPrint 渲染 HTML 到 PDF。模板文件从 `templates/` 读取（只读），输出到 `workspace/output/`（可写）。

## 7. 注入环境变量

脚本运行时平台注入：

| 变量名 | 值 |
|--------|---|
| `SKILL_ROOT` | `/skill/skills/client-finder` |
| `SKILL_WORKSPACE` | `/work` |
| `SKILL_SESSION_ID` | 会话 ID |
| `ALIBABA_SEARCH_TOKEN` | 按清单白名单注入 |
| `PYTHONUTF8` / `PYTHONIOENCODING` | `1` / `utf-8` |

脚本中所有路径构造改为基于这些变量。

## 8. 报告质量预期管理

P1 报告在数据支撑上显著弱于原版。需在报告模板与正文中显式标注。

| 位置 | 标注 |
|------|------|
| 报告封面 | 添加"数据来源受限版本"水印或说明 |
| L0 报告导读 | 首段说明"当前数据源：公开搜索；部分维度依赖推断，置信度标注已体现" |
| 1.2 匹配度诊断 | 数据不充分的维度标注"数据不充分·取中性分" |
| 1.4 关键决策人 | 无脉脉数据时标注"公开社交平台未能识别到决策人" |
| 附录 A 数据采集日志 | 记录调用的工具来源，突出"alibaba_search"，让读者知道数据范围 |

正文工作流中也需说明：能找到的信息类型、置信度判断依据、哪些维度会受影响。

## 9. 验收清单

**加载期**
- [ ] `agents/discover/` 目录结构符合智能体包规范
- [ ] `AGENT.md` 与 `SKILL.md` 可被注册表成功加载
- [ ] 脚本中无绝对路径（grep 验证）
- [ ] 脚本声明、参考文档声明、门禁声明全部指向存在的文件

**路由期**
- [ ] 输入"帮我找做汽车电子的客户" → 一级路由命中 `eitia`
- [ ] 二级路由命中 `client-finder`
- [ ] 装配阶段成功启动 `alibaba_search`
- [ ] 工具就绪事件显示核心工具数 + 目录规模

**执行期**
- [ ] 模型能通过 `search_tools` 检索到搜索工具
- [ ] 模型调用搜索工具成功返回结果
- [ ] 脚本工具能成功执行（stdin/stdout 契约正常）
- [ ] 脚本产出文件落在工作区 `output/` 内
- [ ] 产物登记为可下载，前端显示下载卡片
- [ ] 放宽后的门禁能通过

**多会话**
- [ ] 两个会话并发执行 EITIA，产物互不覆盖
- [ ] 两个会话的工作区完全隔离
- [ ] 共享 MCP 服务只有一个进程
- [ ] 会话结束后 MCP 引用计数正确递减

**报告质量**
- [ ] 报告已标注数据来源受限
- [ ] 八维评分中数据不充分的维度标注中性分
- [ ] 无脉脉数据时已标注降级信息
- [ ] 附录 A 记录的工具来源清晰反映数据范围

**代码规范**（CLAUDE.md）
- [ ] 平台代码中无 `eitia` / `alibaba_search` 等字面量（除配置文件）
- [ ] 变更文件通过 `ruff check` 与 `mypy`
- [ ] 无阻塞调用混入 async 路径
- [ ] 跨边界模型全用 pydantic

## 10. P2 数据源恢复路径

当其他 MCP 服务可用时，渐进恢复：

1. 在 MCP 注册表新增条目
2. 在 `SKILL.md` 依赖段新增，标记可选并附降级说明
3. 正文工作流改为"优先使用专有数据源，不可用时降级搜索"
4. 逐步恢复原有门禁

每恢复一个数据源就恢复一部分维度的数据质量，不等全部就绪。

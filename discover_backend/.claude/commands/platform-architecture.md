# 多智能体平台总体架构

## 适用场景 / 何时触发

- 需要理解整体分层、目录边界、模块依赖方向时
- 新增顶层模块、调整目录结构、判断某段逻辑该放哪一层时
- 生成项目骨架前的第一份必读规范
- 判断某项能力属于「平台」还是属于「某个智能体」时

> 单项细则不在本文件：智能体包契约见 `agent-package-spec.md`；技能装配见 `skill-assembly-spec.md`；工具暴露见 `tool-broker-spec.md`；MCP 接入见 `mcp-integration-spec.md`；**Agent Runtime V2（Workflow + Bounded ReAct + Policy + Contract + Checkpoint）见 `react-runtime-v2-architecture.md`**（V1 graph-runtime-spec 已删除）；LLM 调用见 `llm-provider-spec.md`；SSE 与打字机见 `sse-streaming-spec.md`；脚本执行见 `script-sandbox-spec.md`。

## 1. 平台定位

这是一个**多智能体承载平台**，不是单个智能体。discover 客户发现只是第一个入驻的专家，后续会有更多。

平台提供的：运行时（图循环）、工具接入（MCP + 脚本）、会话与隔离、流式输出、产物管理。

平台不提供的：任何具体业务逻辑、任何具体数据源知识、任何具体报告模板。这些一律属于智能体包自身。

**核心判据**：如果某项能力换一个智能体就不需要了，它就不属于平台。

## 2. 设计红线

| # | 红线 | 违反判定方式 |
|---|------|-------------|
| 1 | 平台代码中不得出现任何智能体名、技能名、MCP server 名、工具名、模板名 | 全局搜索这些字面量，命中即违规 |
| 2 | 智能体包不得引用平台模块 | 智能体的脚本只能通过标准流与环境变量与平台交互 |
| 3 | 平台与智能体包的唯一耦合面是清单文件（AGENT 清单 + SKILL 清单） | 新增耦合面必须先改 `agent-package-spec.md` |
| 4 | 流程控制写在图与脚本里，不写成自然语言提示词 | 参见 CLAUDE.md 技术栈 LangGraph 条 |
| 5 | 所有阈值、路径、密钥、模型名走 pydantic-settings | 代码中出现字面量 URL、绝对路径、超时数字、模型名即违规 |
| 6 | 跨边界对象一律 pydantic 模型 | 清单、事件、工具描述、执行结果用 dataclass 即违规 |
| 7 | 对话接口契约（chat-messages） | streaming 必须逐字符节流走 SSE；blocking 返回 JSON |
| 8 | 智能体之间零共享可写状态 | 任一智能体能读写另一智能体的目录即违规 |

## 3. 分层与依赖方向

依赖严格自上而下，禁止反向引用。

```
L5  前端 Chat UI
      消费事件流，渲染打字机
      不感知智能体内部结构、不感知 MCP、不感知图
              │  SSE（事件判别，单向）
              ▼
L4  接入层
      鉴权、会话生命周期、事件编码与心跳、产物下载
              │
              ▼
L3  运行时层（Agent Runtime V2）
      Workflow 决定当前阶段 → 阶段内 Bounded ReAct → Policy 确定性约束
      → Tool Runtime 管线 → Contract 判定完成 → Checkpoint 持久化 → Event 输出
      思考内容与正文的分离、预算/无进展/死循环硬边界（见 react-runtime-v2-architecture.md）
              │
              ▼
L2  装配层
      AgentRegistry：扫描智能体包、构建索引、热重载
      SkillAssembler：在选定智能体内部选技能、装配上下文
      ToolBroker：统一工具目录、三级暴露、分发、并发与降级
              │
              ▼
L1  执行层
      LLM 客户端（OpenAI 兼容协议，httpx 直连，流式）
      MCP 客户端（远程 Streamable HTTP）
      脚本执行器（P1 宿主 subprocess 直跑，见 script-sandbox-spec §0）
      智能体工作区、Blob 产物存储、去重历史仓库
              │
              ▼
L0  数据层（非代码）
      agents/ 智能体包目录
      配置文件与环境变量
```

**关键约束**：L3 不认识 MCP、不认识脚本、不认识具体智能体。它只向 L2 要「当前可用工具」与「当前该注入的上下文」。

## 4. 目录结构

```
项目根/
├── app/            平台代码（不含任何业务）
│   ├── config/                     配置：Settings 定义与加载
│   ├── protocol/                   对外契约：SSE 事件模型
│   ├── errors/                     领域异常
│   ├── db/                         SQLAlchemy 引擎、ORM 模型（PostgreSQL）
│   ├── history/                    推荐历史仓库（dedup_clues 表读写，脚本纯计算）
│   ├── storage/                    Blob Engine：文件存储抽象 + 本地实现
│   ├── api/                        L4 接入层
│   ├── runtime/                    L3 运行时（图装配与执行）
│   ├── registry/                   L2 智能体与技能装配
│   ├── tools/                      L2 工具代理 + L1 执行器
│   ├── llm/                        L1 LLM 客户端
│   └── session/                    L1 会话、工作区、产物
│
├── agents/                         智能体包（只读代码 + 配置）
│   └── <agent-id>/                 一个智能体一个目录
│       ├── AGENT.md                智能体清单（身份 + 全局约束 + 技能索引）
│       └── <skill-id>/             三级结构：技能目录直接挂智能体下
│           ├── SKILL.md            技能清单 + 工作流正文
│           ├── references/         按需加载的知识文档
│           ├── scripts/            该技能的可执行脚本
│           ├── schemas/            脚本入参约束
│           └── templates/          该技能的模板与静态资源
│
├── workspaces/                     智能体工作区（运行时状态，按 agent 键控、跨会话共享）
├── storage/                        本地文件存储（UUID 扁平，Blob Engine）
├── config/                         平台配置（非密钥）
│   ├── mcp-servers.yaml            MCP 接入注册表
│   └── llm-providers.yaml          模型提供方注册表
├── alembic/                        数据库迁移
└── .env.example                    环境变量样例（仓库唯一允许提交的 env）
```

## 5. 智能体隔离原则

这是多智能体平台与单智能体工具的核心差异。

| 隔离维度 | 规则 |
|---------|------|
| 目录 | 每个智能体独立目录，平台通过智能体 ID 定位，不做跨目录访问 |
| 技能命名空间 | 技能 ID 只需在所属智能体内唯一，不要求全局唯一 |
| 工具命名空间 | 工具限定名带智能体前缀，杜绝跨智能体重名 |
| 模板与脚本 | 只能位于所属技能目录，不得跨智能体引用 |
| 工作区 | 智能体工作区按「智能体」维度隔离（按 agent 键控、跨会话共享），不同智能体互不可见 |
| MCP 依赖 | 各智能体独立声明，平台按引用计数管理进程，但会话态服务器按会话独占 |
| 配置 | 各智能体可有独立配置段，平台合并时智能体段优先级高于全局默认 |

**跨智能体协作**（后续需要时）只能通过平台层显式转交：一个智能体产出结构化结果，平台把结果作为输入交给另一个智能体。不允许智能体直接调用另一个智能体的脚本或读它的目录。

## 6. 助手选择与技能解析

用户**显式选择**助手（专家 / 通用），**不做 LLM 路由识别**。目录接口 `GET /api/v1/assistants`（聚合入口，只读，非审批）返回用户可选列表：专家（来自 agents/ 包）；通用对话为未绑定默认，不列入目录。

```
用户选择（经 /assistants 目录）
   │
   ├─ 一级：解析助手（AssistantResolver）
   │    依据：会话显式绑定（assistant_target）
   │    来源：用户选择（专家 / 通用），非模型识别
   │    通用 / 未绑定 → 通用对话；专家 → 进入二级
   │
   ├─ 二级：解析技能（SkillResolver，确定性策略链）
   │    显式技能 → 默认技能 → 唯一技能 → 首个技能
   │    输入：只含选定智能体的技能，不含其他智能体
   │
   └─ 装配：注入智能体全局约束 + 技能工作流 + 该技能核心工具
```

会话内已确定智能体后，后续轮次**不再重复一级解析**。切换通过用户显式重选（会话绑定变更），不靠关键词或模型识别。

理由：中途重做解析会丢失已装配的上下文与工具，且用户预期是「一次进入某个智能体后持续对话」。

## 7. 主流程

```
1. 建会话
     分配会话 ID，创建会话工作区骨架

2. 开 SSE 流
     立即发送会话建立事件与首个心跳，让前端确认连接可用

3. 解析助手：读用户显式选择
     会话绑定 assistant_target（用户选择）
     通用 / 未绑定则进入通用对话分支

4. 二级路由 + 装配
     选定技能，注入智能体约束与技能工作流
     启动该技能声明的 MCP 依赖
     必需依赖不可用 → 发错误事件并终止本轮
     可选依赖不可用 → 记降级、发降级事件、注入降级说明
     发工具就绪事件

5. 阶段执行（V2 Bounded ReAct，见 react-runtime-v2-architecture.md §10）
     Workflow 推进当前阶段 → 阶段内 ReAct 循环：
       模型思考 → 思考内容以独立事件类型流出（与正文分离）
       模型正文 → 逐字符节流流出
       模型请求工具 → Policy 预检 → Tool Runtime 管线执行 → 结果事件流出
       产出文件 → 登记产物、发产物事件
       预算 / 无进展 / 死循环 → 硬边界终止并产出部分结果（§10.2/§12.4）
     阶段完成经 complete_phase 控制工具 → Contract 判定 → 推进或修复（§9.3）

6. 收尾
     发完成事件，关闭流
     释放 MCP 引用计数（必须在异常路径也执行）
```

## 8. 关键取舍

| 取舍 | 决定 | 理由 |
|------|------|------|
| 是否提供任意 shell 与文件编辑工具 | 不提供 | Web 多租户无法安全暴露；改为脚本白名单制 |
| 是否预注入全部 MCP 工具 | 不预注入 | 工具数量增长会吃满上下文并降低选择准确率，改用三级暴露 |
| 是否预注入全部参考文档 | 不预注入 | 改为按需读取，由模型自行判断何时需要 |
| 执行内核 | Workflow 控制 + 阶段内 Bounded ReAct | 引擎拥有控制权，LLM 只有建议权；Policy/Contract 确定性约束；新增智能体不改内核（见 react-runtime-v2-architecture.md §5/§26） |
| 对话传输 | chat-messages（streaming SSE / blocking JSON） | 客户端按 `response_mode` 选择；streaming 单向流更易穿透代理且适配打字机 |
| 思考内容 | 独立事件类型 | 前端需分区渲染，与正文混流会导致无法折叠 |
| 脚本隔离 | P1 宿主直跑，对外开放脚本编辑时再引入轻量沙箱 | 可信内部脚本，容器隔离属过度设计（2026-08 决策） |
| 模板与脚本归属 | 归属技能，不归平台 | 换智能体就不需要的东西不属于平台 |

## 9. 分期交付

| 阶段 | 范围 | 验收标准 |
|------|------|---------|
| P1 | 单智能体端到端：助手选择 + 技能解析 + 装配 + 阶段内 Bounded ReAct + SSE 打字机 + 思考流 + 宿主直跑脚本 + 单一搜索类 MCP | 首个入驻智能体（`discover`）走通全流程并产出报告 |
| V2 | Agent Runtime V2 内核：契约 + Bounded ReAct + Policy + Contract + Checkpoint + Run API（见 react-runtime-v2-architecture.md） | 单阶段内核全链路可测；W8 灰度切换后下线 V1 Runtime |
| P2 | 规模化：三级工具暴露 + 按需文档 + 并发与降级 + 上下文预算裁剪 | 工具数量增长后首轮上下文仍在预算内 |
| P3 | 多智能体：智能体注册与热重载 + 产物管理 + 工作区隔离验证 | 两个以上智能体共存，多会话并发无互串 |
| P4 | 加固：门禁校验器 + 健康看板 + 资源配额 + 审计日志 | 第三方智能体包可安全装载 |

## 10. 平台配置项

按 CLAUDE.md 配置驱动要求，全部走 pydantic-settings，扩展开关统一命名。

| 配置项 | 用途 |
|--------|------|
| 智能体包根目录 | 定位 agents/ |
| MCP 注册表路径 | 定位 mcp-servers.yaml |
| 模型提供方注册表路径 | 定位 llm-providers.yaml |
| 智能体工作区根目录 | 定位工作区落盘位置（按 agent 键控） |
| 数据库连接串 | SQLAlchemy 异步连接串（PostgreSQL，asyncpg） |
| 存储根目录 | Blob Engine 本地存储落盘位置 |
| 默认模型标识 | 一级路由与通用对话用 |
| 模型接入密钥 | 走环境变量，密文类型 |
| 思考模式开关与强度 | 控制是否请求思考内容及其详细程度 |
| 打字机节流间隔 | 控制逐字符输出的时间间隔 |
| 打字机每帧字符数 | 控制每次推送的字符数量 |
| 心跳间隔 | 防代理超时断流 |
| 单批工具并发上限 | 全局并发闸门 |
| 单服务器并发上限 | 防上游限流 |
| 工具默认超时 | 单次工具调用上限 |
| MCP 空闲回收阈值 | 无引用后多久停止 |
| MCP 启动握手超时 | 建连上限 |
| 脚本执行超时 | 宿主直跑脚本的总时长上限（先 terminate 再 kill） |
| 脚本输出截断上限 | 防 stdout 打爆内存，边读边限 |
| 工具输出截断上限 | 防上下文被单次结果打爆 |
| 单轮上下文预算 | 触发裁剪的阈值 |
| 推理循环轮次上限 | 防无限循环 |
| 热重载开关 | 是否监听智能体包变更 |

仓库只提交样例文件，禁止提交真实环境变量文件。

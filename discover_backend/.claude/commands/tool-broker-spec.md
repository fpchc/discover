# 工具代理与三级暴露策略

## 适用场景 / 何时触发

- 实现工具注册、检索、分发、并发控制、降级时
- MCP 工具数量增长导致上下文被参数说明吃满时
- 需要处理工具重名、工具超时、工具输出截断时
- 判断某个工具该放哪一级时

---

## 1. 要解决的问题

当接入的 MCP 服务增多、工具总数达到数十上百时，全量注入会遇到三个问题：

| 问题 | 后果 |
|------|------|
| 上下文被参数说明吃满 | 数十个工具的完整参数约束会占数万 token，挤占对话与推理空间 |
| 模型选择准确率下降 | 在近百个相似工具间选择，模型更易选错或遗漏最优工具 |
| 重名冲突 | 不同 MCP 服务可能提供同名工具，无命名空间无法区分 |

解法是三级暴露加命名空间强制前缀。

---

## 2. 三级结构

```
Tier 0  元工具（任何会话常驻，3 个）
        
        search_tools        按查询检索工具目录，返回名称与简要说明
        describe_tool       返回指定工具的完整参数约束
        read_reference      按需读取当前技能的参考文档
        
                 ↓  模型检索到需要的工具
        
Tier 1  核心工具（技能激活即注入完整参数约束，建议 ≤ 15 个）
        
        来源：技能清单中 MCP 依赖的核心工具列表 + 该技能全部脚本工具
        
                 ↓  模型首次需要时
        
Tier 2  懒加载工具（仅在目录中可被检索，参数约束按需展开）
        
        来源：已激活 MCP 服务声明的其余全部工具
```

**调用路径示例**：模型用 `search_tools("企业风险")` 找到若干候选工具名 → 用 `describe_tool("<server>.<tool>")` 拿参数约束 → 构造参数直接调用该工具。工具代理允许调用目录中任何已激活服务的工具，不要求先描述；但模型不知道参数就会调错，实践上会自然先描述。

---

## 3. 命名空间

强制前缀，杜绝重名，也让模型看名字就知道工具来源。

| 来源类型 | 前缀规则 | 示例 |
|---------|---------|------|
| MCP 服务 | 服务标识加点号 | `tencent_mcp.web_search_tencent` |
| 技能脚本 | 智能体 ID + 技能 ID + `script.` | `discover.client_finder.script.score_calculator` |
| 元工具 | 无前缀 | `search_tools` |

服务标识中的连字符转下划线（保证工具名符合命名约束）。转换规则集中在一处，不散落。

---

## 4. 工具描述符模型

工具代理维护统一目录，每条记录为一个描述符。

| 字段 | 用途 |
|------|------|
| 限定名 | 带命名空间的完整名称 |
| 短名 | 不带命名空间的原始名称 |
| 命名空间 | 前缀部分 |
| 简要说明 | 一句话用途，供检索时返回 |
| 参数约束 | 完整 JSON Schema |
| 来源类型 | MCP / 脚本 / 元工具 |
| 层级 | 0 / 1 / 2 |
| 副作用类型 | 描述符元数据（脚本/服务来源声明，不再驱动审批） |
| 超时上限 | 缺省取平台配置 |
| 原始来源 | 服务标识或脚本相对路径，用于分发 |

描述符在装配期生成，不在运行时构造。

---

## 5. 工具代理职责边界

工具代理**负责**：

- 维护目录与索引
- 提供检索与描述接口
- 分发调用到 MCP 客户端或脚本执行器
- 统一并发控制与超时
- 分类错误并附降级建议
- 截断超长输出

工具代理**不负责**：

- 启动 MCP 服务（归 MCP 集成层）
- 执行脚本（归脚本执行层）
- 决定哪些工具该暴露（归技能装配层）
- 重试（归图运行时层）

理由是单一职责：工具代理是分发中枢，不做具体执行也不做策略决策。

---

## 6. 并发控制

两层信号量，必须同时满足：

| 层级 | 作用 | 限额来源 |
|------|------|---------|
| 全局 | 防一批工具调用总数过大 | 平台配置的单批上限 |
| 单服务 | 防把上游 API 打到限流 | 平台配置的单服务上限或 MCP 注册表的服务专属上限 |

并发执行用异步收集，异常统一转为失败结果（不向上抛）。返回列表与入参列表下标一一对应。

**为什么需要单服务上限**：一批二十个调用全打向同一个计费 API，常超出其限流阈值。单服务上限是必需的，不是优化。

---

## 7. 超时与降级

| 情况 | 处理 | 结果字段 |
|------|------|---------|
| 单工具超时 | 取消任务 | 成败标志为假、错误类别为超时、建议为"缩小输入或分批" |
| 服务进程崩溃 | 由 MCP 集成层重启一次，仍失败则本次失败 | 成败标志为假、错误类别为服务错误、建议为降级通道 |
| 工具不在目录 | 检索最相近的三个名称 | 成败标志为假、错误类别为未找到、建议为候选名称 |
| 参数不符约束 | 提取约束校验错误 | 成败标志为假、错误类别为参数非法、建议为该工具完整约束 |

**结果必须包含面向模型的下一步建议**。裸异常字符串让模型不知如何继续，带建议的失败结果让模型知道「该换另一个工具」或「该调整参数重试」。

超时时间优先级：描述符的超时上限 > 平台配置的默认超时。

---

## 8. 输出截断

单次工具返回数千行会直接炸上下文，必须截断。

| 规则 | |
|------|---|
| 截断阈值 | 平台配置，典型值数千字符 |
| 截断位置 | 保留头部（多数 API 关键字段在前） |
| 截断标识 | 追加省略提示并标注原始长度 |
| 标志回传 | 结果中截断标志位为真 |
| 完整保存 | 原文写会话工具日志目录，供审计与前端查看完整结果 |

结构化输出优先保留头部而非尾部，理由是 API 响应通常把元信息与汇总放前面、详情列表放后面。截到一半的列表仍有价值，截掉元信息则完全不可用。

## 9. 元工具实现要点

**search_tools**

- 输入：查询词、返回上限
- P1 实现：在简要说明与短名上做关键词匹配与简单打分
- P2 优化：改用向量检索（工具说明预先嵌入并缓存）
- 输出：限定名、简要说明、来源类型；**不包含参数约束**

不返回约束是关键——返回约束就失去分层意义了，检索只是索引，描述才展开细节。

**describe_tool**

- 输入：限定名
- 输出：完整描述符，含参数约束
- 副作用：把该工具加入本会话暴露集合（用于生成可用工具列表）
- 工具不存在时不抛错，返回最相近的候选供模型选择

**read_reference**

- 输入：相对路径，可选章节标识
- 校验：只允许当前激活技能目录下的 references 子目录，路径规范化后检查前缀
- 去重：已在会话已加载文档集合中则返回"已在上下文"
- 分段：超长文档按标题分段，支持只读某一段
- 副作用：记入已加载集合

## 10. 目录构建时机

| 时机 | 操作 | 包含内容 |
|------|------|---------|
| 平台启动 | 构建元工具描述符 | Tier 0 |
| 技能激活 | 从技能清单提取 MCP 核心工具与脚本工具，构建描述符并标为 Tier 1 | Tier 0 + Tier 1 |
| MCP 服务启动完成 | 取该服务的工具列表，去除已在 Tier 1 的，剩余标为 Tier 2 | Tier 0 + Tier 1 + Tier 2 |
| 模型调用 describe_tool | 把该工具移入暴露集合 | 运行时扩展 |

目录在技能激活时构建，MCP 启动时扩充。会话结束时回收该会话的目录与暴露集合。

**能力依赖（failover）**：技能声明 `capability_dependencies` 能力而非具体服务时，激活按
注册表 `capabilities` 的候选服务器顺序尝试，首个可用者生效并扩充目录，其余失败候选标记
降级；必需能力全部候选失败则拒绝激活，可选能力全部失败则降级继续。工具限定名
（`{server}.{tool}`）仍以实际生效的服务标识命名。

## 11. 执行结果模型

| 字段 | 用途 |
|------|------|
| 调用标识 | 关联到发起时的调用 |
| 限定名 | 哪个工具 |
| 成败标志 | 布尔 |
| 内容 | 已截断的、可直接进上下文的文本 |
| 错误类别 | 失败时的分类：超时、未找到、参数非法、服务错误、拒绝 |
| 错误建议 | 面向模型的下一步行动提示 |
| 耗时 | 毫秒 |
| 是否截断 | 布尔 |
| 完整日志路径 | 供前端取完整原文 |

失败时错误建议字段**必须非空**，不能只给分类不给建议。

---

## 12. 自检清单

- [ ] 平台代码中无任何具体工具名（元工具除外）
- [ ] 工具名转换规则只有一处实现
- [ ] 分发从不向上抛异常，一律返回结果对象
- [ ] 失败结果必含建议字段
- [ ] 并发返回顺序与入参一致
- [ ] 单服务并发受独立信号量控制
- [ ] read_reference 有路径穿越防护
- [ ] 截断后原文可从日志目录取回
- [ ] 检索不返回参数约束，只返回名称与简要说明

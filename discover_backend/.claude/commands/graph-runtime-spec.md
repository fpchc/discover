# LangGraph 运行时规范

## 适用场景 / 何时触发

- 实现图装配、状态定义、节点逻辑、边条件、持久化时
- 需要新增节点、调整路由条件、改变推理循环策略时
- 实现门禁校验、会话恢复时
- 排查轮次失控、上下文裁剪错误、中断恢复失败时

---

## 1. 图的定位

图**只提供执行环境**，不承载业务流程。业务流程知识在智能体与技能清单的正文里。

因此拓扑刻意保持极简：两级解析 + 一个推理循环。新增智能体永远不需要改图。

> 「迁移后目标」：一级解析（resolve_assistant）读**用户显式选择**（会话绑定），不做 LLM 路由识别。

**判断标准**：如果你想给图加节点来表达某个智能体的某个步骤，那就走错了——该步骤应该写进那个智能体的清单或做成脚本工具。

## 2. 拓扑

```
                    START
                      │
                      ▼
            ┌──────────────────┐
            │resolve_assistant │  解析用户选择：读会话显式绑定
            │  (非 LLM 路由)    │
            └─────┬────────┬───┘
        绑定专家   │        │ 未绑定 / 通用
                  ▼        ▼
      ┌──────────────┐  ┌──────────────┐
      │ resolve_skill│  │ generic_chat │
      │ 确定性选技能  │  │  通用对话     │
      └──────┬───────┘  └──────┬───────┘
             ▼                  │
      ┌──────────────┐          │
      │ assemble     │          │
      │ 装配上下文+工具│          │
      └──────┬───────┘          │
             ▼                  │
       ┌──────────────┐         │
   ┌──▶│    agent     │         │
   │   │  模型推理     │         │
   │   └──┬────────┬──┘         │
   │      │        │ 无工具调用   │
   │  有工具│        └────────────┤
   │  调用 ▼                     │
   │   ┌──────────────┐          │
   └───│  tool_node   │          │
       │  并发执行     │          ▼
       └──────────────┘        END
```

边定义：

| 起点 | 类型 | 目标 | 条件 |
|------|------|------|------|
| START | 固定 | resolve_assistant | — |
| resolve_assistant | 条件 | resolve_skill / generic_chat | `active_target.type` 为 expert → resolve_skill；否则 generic_chat |
| resolve_skill | 固定 | assemble | — |
| assemble | 固定 | agent | — |
| agent | 条件 | tool_node / END | 有工具调用 → tool_node；否则 END |
| tool_node | 固定 | agent | — |
| generic_chat | 固定 | END | — |

循环上限：`agent ⇄ tool_node` 设最大轮次，达限注入"已达轮次上限，请基于现有信息给出结论"并强制走 END。

## 3. 状态模型

| 字段 | 类型 | 累加器 | 说明 |
|------|------|:---:|------|
| messages | 消息列表 | add_messages | LangGraph 标准累加器 |
| session_id | 字符串 | — | 会话标识 |
| workspace_path | 路径对象 | — | 工作区绝对路径 |
| active_target | AssistantTarget 或空 | — | 当前助手选择（type + id；expert 时 id=智能体 ID） |
| active_skill | 字符串或空 | — | 当前技能 ID |
| route_reason | 字符串或空 | — | 路由理由 |
| loaded_references | 字符串集合 | — | 已注入的参考文档路径，防重复 |
| exposed_tools | 字符串列表 | — | 当前暴露的工具限定名 |
| gate_status | 门禁结果字典 | — | 键为门禁 ID，值含是否通过、失败项、检查轮次 |
| degraded_sources | 字符串列表 | — | 降级的数据源标识 |
| artifacts | 产物列表 | add | 已产出文件 |
| turn | 整数 | — | 推理轮次 |

状态模型用 pydantic，跨边界传递。工作区路径用路径对象是运行时句柄，序列化器需转换为字符串形式。

## 4. 节点职责

### resolve_assistant（一级解析：用户选择）

1. 调 `AssistantResolver` 读**会话显式绑定**（`session.assistant_target`，用户选择）
2. 绑定与 `active_target` 一致 → 沿用（跳过本节点）
3. 绑定变更（切换）→ 清 `active_skill`、重置装配快照，重新进入
4. 无绑定 / type=generic → 走 `generic_chat`；写 `active_target`，发智能体选定事件（`source=user`）

> 本节点**不做 LLM 路由**。选择来自用户，不是模型识别。

### resolve_skill（二级解析：确定性选技能）

1. 取当前智能体的技能索引（仅 ID、职责、适用边界、触发词）
2. `SkillResolver` 策略链解析：显式技能 → 默认技能 → 唯一技能 → 首个技能
3. 写 `active_skill` / `route_reason`，发技能选定事件

> 确定性策略，不做 LLM 识别。未来策略（权限 / 上下文感知）追加进策略链，不改核心流程。

### assemble（装配）

1. 读取智能体清单与技能清单
2. 注入系统消息：智能体全局约束 + 技能工作流 + 参考文档清单（含加载时机）
3. 调用工具代理激活该技能（启动 MCP 依赖、注册脚本工具）
4. 必需依赖不可用 → 发错误事件并终止
5. 可选依赖不可用 → 记 `degraded_sources`，发降级事件，注入降级说明
6. 写 `exposed_tools`，发工具就绪事件

### agent（推理）

1. 从工具代理获取当前暴露工具列表
2. 分离思考内容与正文，分别流出（思考走独立事件类型）
3. 逐字符节流推送正文
4. `turn` 自增；达轮次上限则注入收尾提示并结束
5. 上下文超预算 → 裁剪早期工具结果（保留系统消息、最近 N 轮、全部用户消息）

### tool_node（工具执行）

1. 调用工具代理批量执行
2. 每个结果发工具完成事件（含成败、摘要、耗时）
3. 产出文件的结果 → 产物存储登记 → 发产物事件
4. 调用的是门禁校验器 → 写 `gate_status`，发门禁事件
5. 全部结果转消息追加到 `messages`

### generic_chat（通用对话）

无智能体命中时的兜底。工具只有 Tier 0 元工具，让模型能检索"有没有相关智能体"并提示用户。

## 5. 上下文预算裁剪

单轮上下文超预算时触发裁剪。

| 保留 | 裁剪 |
|------|------|
| 系统消息 | 不可裁 |
| 用户消息 | 全保留 |
| 助手正文消息 | 保留最近 N 轮 |
| 工具结果消息 | 按时间倒序保留，超预算的裁掉 |
| 思考内容 | **不进历史**，本就不占预算 |

裁剪策略可配置：激进模式只保留最近几轮，温和模式尽量多保留。

思考内容不进历史是关键设计——它体量大但对后续推理的边际价值低，写回会迅速吃满上下文。

---

## 6. 门禁执行

技能清单的门禁声明转为两种形式：

**有校验器**：注册为脚本工具 `<agent>.<skill>.script.gate_<id>`，模型调用后 `tool_node` 写 `gate_status`。未通过时把失败项列表回给模型，要求原地修复后重新校验。阻断型门禁未通过则禁止进入声明的下一阶段。

**无校验器**：注入为 checklist 提示词，靠模型自检。这是弱门禁。

校验器契约：退出码非零表示未通过，标准输出给出结构化失败项。

## 7. 持久化与中断恢复

| 项 | 方案 |
|---|------|
| Checkpointer | P1 内存版；P3 换 SQLite 或 Postgres |
| thread_id | 等于 session_id |
| 恢复语义 | 从最后 checkpoint 继续；MCP 可能已回收，重启时重新确保 |

---

## 8. 重入保护与显式切换

**会话内已确定智能体后，后续轮次不再重复一级解析**。切换只能通过用户显式重选（会话绑定变更），不靠关键词。

理由：重做解析会丢失已装配的上下文与工具，且用户预期是"一次进入某个智能体后持续对话"。

判定方式：`session.assistant_target` 与 `active_target` 一致 → 沿用；不一致 → 按新绑定切换并重装配。

## 9. 自检清单

- [ ] 图中无任何智能体名、技能名、工具名
- [ ] 图中无 LLM 路由工具（`select_agent` / `select_skill`）
- [ ] 节点函数全异步且返回类型显式标注
- [ ] 单函数不超过 30 行，细节抽私有辅助函数
- [ ] 推理循环有轮次上限
- [ ] 后续轮次不重复一级解析（仅读会话绑定）
- [ ] 思考内容不回填对话历史
- [ ] 会话结束时 MCP 引用计数递减（异常路径亦然）
- [ ] 无阻塞调用混入节点
- [ ] 状态模型全字段显式标注类型

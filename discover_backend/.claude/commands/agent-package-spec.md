# 智能体包契约规范

## 适用场景 / 何时触发

- 新增一个智能体、或修改现有智能体的清单文件时
- 实现智能体注册、扫描、索引、热重载逻辑时
- 判断「某项内容该写进智能体清单、技能清单，还是正文」时
- 判断「某个脚本或模板该放哪一层」时

> 这是平台与智能体之间的耦合面。任何新增字段必须先改本文件，再改实现。

---

## 1. 两级清单结构

平台需要区分「智能体身份」与「技能能力」，因此有两级清单。

```
agents/<agent-id>/
├── AGENT.md                 一级清单：智能体身份、全局约束、技能索引
└── <skill-id>/              三级结构：技能目录直接挂智能体下（agents/{agent}/{skill}）
    ├── SKILL.md             二级清单：技能适用边界、依赖声明、工作流正文
    ├── references/          按需加载的知识文档
    ├── scripts/             该技能专属脚本
    ├── schemas/             脚本入参约束定义
    └── templates/           该技能专属模板与静态资源
```

**归属判定**：技能专属资源一律放该技能目录；多个智能体都用 → 说明它是平台能力，应做成 MCP 服务或平台内置工具，**不允许跨智能体目录引用**。

---

## 2. AGENT 清单字段

清单头部为结构化元信息，正文为该智能体的全局行为约束。

| 字段 | 必需 | 说明 |
|------|:---:|------|
| kind | 是 | 清单类型判别：当前仅 `agent`（专家智能体包）。skill / workflow 属未来独立 kind，**不是 agent 类型** |
| type | 否 | agent kind 下的细分：当前仅 `expert`（类 Claude Code 的复杂工具包：MCP + 脚本 + 技能）。默认 `expert` |
| 智能体 ID | 是 | kebab-case，须等于目录名，全局唯一；**不得为保留字 `generic`**（目录接口内置通用项占用） |
| 显示名称 | 是 | 前端展示用 |
| 版本 | 是 | 语义化版本 |
| 一句话职责 | 是 | 前端列表展示 |
| 适用边界 | 是 | **一级路由的主要依据**，须同时写「适用」与「不适用」 |
| 默认技能 ID | 否 | 二级路由无明确命中时的兜底技能 |
| 模型偏好 | 否 | 建议使用的模型标识，平台配置可覆盖 |
| 思考模式偏好 | 否 | 该智能体是否需要思考内容及强度 |
| 环境变量白名单 | 否 | 该智能体所有脚本可能需要的环境变量名清单 |
| 技能索引 | 是 | 该智能体下所有技能的 ID 列表 |

正文写该智能体的**全局行为约束**：语气、输出规范、通用禁令、跨技能一致的纪律。这部分在任何技能激活时都会注入。

**正文预算**：AGENT 正文应显著短于 SKILL 正文（建议不超过技能正文的三分之一）。它是全局常驻内容，写长了会挤占每一次对话的空间。

## 3. SKILL 清单字段

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 技能 ID | 是 | kebab-case，须等于目录名，在所属智能体内唯一 |
| 版本 | 是 | 语义化版本 |
| 一句话职责 | 是 | 技能索引展示用 |
| 适用边界 | 是 | **二级路由的主要依据**，须同时写「适用」与「不适用」 |
| 触发关键词 | 否 | 仅作快速预筛，不得作为唯一判据 |
| MCP 依赖声明 | 否 | 见下节 |
| 脚本声明 | 否 | 见下节，白名单制 |
| 参考文档声明 | 否 | 见下节 |
| 门禁声明 | 否 | 见下节 |
| 模板声明 | 否 | 该技能使用的模板文件路径与用途 |

正文写该技能的**完整工作流**：阶段划分、执行纪律、输出检查清单。这是激活后注入的主体内容。

## 4. MCP 依赖声明

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 服务器标识 | 是 | 须存在于平台 MCP 注册表 |
| 核心工具列表 | 否 | 激活时直接注入完整参数说明的工具；留空表示全部走按需检索 |
| 是否必需 | 否 | 默认必需。必需且不可用则拒绝激活该技能 |
| 降级说明 | 否 | 可选依赖缺失时注入模型的说明文本 |

**核心工具列表建议控制在十余个以内**。超出则只列最高频的，其余靠检索发现。理由见 `tool-broker-spec.md`。

### 4.1 能力依赖声明（capability_dependencies）

`mcp_dependencies` 点名具体服务器，用于单服务器专有数据源（如天眼查 / 企查查）。
多提供方可互换的搜索类通道**不点名提供方**，改声明平台能力：

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 能力标识 | 是 | 须存在于平台 MCP 注册表的 `capabilities` 段 |
| 核心工具列表 | 否 | 同 4 节 |
| 是否必需 | 否 | 默认必需。必需且该能力全部候选提供方不可用则拒绝激活 |
| 降级说明 | 否 | 可选能力全部候选不可用时注入模型的说明文本 |

**能力由注册表解析为候选服务器列表，运行期主备切换（failover）**：按注册表顺序优先，
第一个可用者生效，其余标记降级。因此加 / 删 / 换提供方只改 `config/mcp-servers.yaml`，
技能清单与正文（含参考文档）一律不出现提供方名称 —— 这是「改动半径」红线（CLAUDE.md §13）
对数据源类需求的落地。正文如需披露数据来源，一律写「平台联网搜索（web_search 能力）」，
真实提供方由运行期工具限定名（`{server}.{tool}`）动态披露。

## 5. 脚本声明

平台采用白名单制：只有清单显式声明的脚本可被调用，模型不能执行任意命令。

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 相对路径 | 是 | 相对技能目录或所属智能体 shared 目录 |
| 工具名 | 是 | 暴露给模型的名称，在所属技能内唯一 |
| 用途说明 | 是 | 面向模型，说明何时该调用它 |
| 入参约束文件 | 否 | 指向 schemas 下的约束定义；缺省则入参为单一文本字段 |
| 超时上限 | 否 | 缺省取平台默认 |
| 副作用类型 | 否 | 缺省为只读。描述脚本工具的副作用（审批已移除，仅作元数据） |
| 去重历史绑定 | 否 | 缺省否。为 true 时平台自动注入 `history` 字段、add 模式经 `_upsert` 回写 dedup_clues 表，脚本保持无状态（见 `script-sandbox-spec.md` §2） |

**副作用类型枚举**：只读、写文件、发起网络调用、对外发布、删除。

路径解析时必须校验：规范化后落在允许的目录内、不是指向外部的符号链接、不含向上穿越。

---

## 6. 参考文档声明

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 相对路径 | 是 | 相对技能目录 |
| 加载时机说明 | 是 | 写给模型判断何时该读这篇 |
| 是否预加载 | 否 | 默认否。为是则技能激活即注入，慎用 |

参考文档默认不预加载。技能激活时只注入「有哪些文档 + 各自何时该读」的清单，模型自行决定何时拉取。

## 7. 门禁声明

门禁是把「流程纪律」从提示词变成可执行校验的机制。

| 字段 | 必需 | 说明 |
|------|:---:|------|
| 门禁 ID | 是 | 在所属技能内唯一 |
| 通过条件描述 | 是 | 人类可读，也用于失败时提示模型 |
| 校验器 | 否 | 指向该技能 scripts 下的可执行校验；缺省则退化为模型自检 |
| 是否阻断 | 否 | 默认阻断。未通过则禁止进入下一阶段 |

**原则**：能写成校验器的门禁就不要只写成提示词。提示词门禁靠模型自觉，跳过无成本；校验器门禁失败会强制返回错误清单要求修复。

校验器契约：退出码非零表示未通过，标准输出给出结构化失败项清单。失败项会原样回给模型要求逐项修复后重新校验。

## 8. 加载期校验

任一项失败则该智能体或技能标记为无效并跳过，**不影响其他智能体**。无效原因需通过接口暴露给前端，便于排查。

**智能体级校验**
- `kind` 仅支持 `agent`（当前）；`type` 仅支持 `expert`（当前）——未来扩展走新 kind，不在此枚举里堆
- 智能体 ID 等于目录名，且全局唯一；不得为保留字 `generic`
- 技能索引中的每个技能 ID 都存在对应目录
- 默认技能 ID（若声明）在技能索引内
- 正文长度在预算内

**技能级校验**
- 技能 ID 等于目录名，在所属智能体内唯一
- 所有声明的脚本、参考文档、入参约束、模板文件均存在
- 所有 MCP 服务器标识存在于平台注册表
- 脚本工具名在技能内唯一
- 所有路径不含向上穿越、不是绝对路径
- 门禁校验器指向该技能 scripts 内的文件
- 脚本中无绝对路径字面量（见下节）

## 9. 绝对路径禁令

智能体脚本中禁止出现绝对路径字面量。这在多会话并发下会导致文件互相覆盖，在容器中路径根本不存在。

平台在加载期扫描智能体的 scripts 目录，命中盘符前缀或根目录起始的路径字面量即报错。

脚本获取路径的**唯一合法方式**是读平台注入的环境变量：

| 环境变量语义 | 指向 |
|-------------|------|
| 技能根目录 | 当前技能目录，只读（脚本读 templates / references） |
| 工作区目录 | 本智能体的可写目录，同时是工作目录（按 agent 键控、跨会话共享） |

具体变量名在 `script-sandbox-spec.md` 定义。

## 10. 索引与热重载

**索引分层**，对应两级路由的输入规模控制：

| 索引层级 | 内容 | 用途 |
|---------|------|------|
| 智能体索引 | 各智能体的 ID、显示名、职责、适用边界 | 一级路由输入 |
| 技能索引 | 指定智能体下各技能的 ID、职责、适用边界、触发词 | 二级路由输入 |

一级路由只看智能体索引，不看任何技能信息。二级路由只看选定智能体的技能索引，不看其他智能体。这样路由输入规模不随平台智能体总数线性膨胀。

**热重载**：由配置开关控制。重载返回本次成功加载列表与无效项及原因。重载不影响进行中的会话——已激活的清单在会话内保持快照语义，避免执行中途规范变化。

## 11. 自检清单

- [ ] 智能体 ID 与技能 ID 均等于目录名
- [ ] 适用边界同时写了「适用」与「不适用」
- [ ] AGENT 正文长度显著短于 SKILL 正文
- [ ] 所有声明的文件路径存在且无穿越
- [ ] 脚本中无绝对路径字面量
- [ ] 模板与脚本未跨智能体引用
- [ ] 核心工具列表控制在十余个以内
- [ ] 阻断型门禁尽量提供了校验器
- [ ] 环境变量白名单已声明，未依赖全量透传

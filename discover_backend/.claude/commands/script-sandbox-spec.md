# 脚本执行规范（P1 本地直跑）

## 适用场景 / 何时触发

- 实现脚本执行器、脚本入参校验、产物登记时
- 排查脚本超时、输出为空、路径不可访问、权限错误时
- 判断某个能力该做成脚本还是做成 MCP 服务时
- 将来若对外开放脚本编辑，重新评估隔离时

---

## 0. 隔离决策（P1，2026-08 用户决策）

**P1 脚本一律宿主 subprocess 直跑（`sys.executable script.py`），不做容器隔离。**
脚本是可信内部代码，不开放给外部人员修改，隔离属于过度设计。

| 项 | 结论 |
|---|---|
| 执行方式 | 宿主 subprocess（`anyio.open_process`），cwd=工作区 |
| 隔离 | 无（P1 不设容器 / 沙箱 / 资源限额） |
| 失去的隔离属性 | 网络阻断、rootfs 只读、capability 剥离、cgroup 限额 |
| 将来（对外开放脚本编辑时） | 重新引入**轻量沙箱**（不一定是完整 Docker），届时再评估 |

代码偏离此前的容器方案处均有 `# pragma: 简化` 标注。

## 1. 执行契约

脚本与平台的唯一接口是标准流与环境变量，不依赖语言。

| 通道 | 用途 | 约束 |
|------|------|------|
| stdin | 入参（UTF-8 JSON） | 单次写入后关闭 |
| stdout | 结果（优先 JSON） | 超限截断 |
| stderr | 日志 | **不进模型上下文**，只写审计 |
| exit code | 0 成功，非 0 失败 | 非 0 时 stderr 尾部进上下文 |
| 环境变量 | 路径与凭据 | 固定注入 + 清单白名单覆盖 |

stdout 不是合法 JSON 时按纯文本处理，不报错——允许脚本打印人类可读文本。

---

## 2. 环境变量注入

脚本环境 = 宿主环境 + 固定注入项 + 清单白名单覆盖。

| 变量语义 | 值 | 说明 |
|---------|---|------|
| 技能根目录 | `<agent-dir>/<skill-id>` | 脚本读自己的 templates / references |
| 工作区目录 | `<workspace>` | 读写，同时是工作目录（cwd），按 agent 键控、跨会话共享 |
| 编码相关 | UTF-8 相关变量 | 固定 UTF-8，防中文乱码 |
| 技能声明的白名单 | 按清单 `env_keys` 字段 | 如 API 令牌（作为覆盖层） |

**去重历史绑定（`history_store`）**：声明 `history_store: true` 的脚本为无状态纯计算——平台把去重历史（dedup_clues 表）经 stdin 的 `history` 字段注入；add 模式脚本在结果 `_upsert` 字段返回新线索，平台持久化后从模型可见输出中剥离该字段。脚本自身不得再读写历史文件。

## 3. 生命周期

```
1. 准备
     构造启动命令（当前解释器 + 脚本绝对路径）
     合并环境变量（宿主 + 注入 + 白名单）
     
2. 启动
     python <script>（cwd=工作区）
     stdin 管道准备好
     
3. 输入
     一次性写入 JSON 到 stdin
     关闭 stdin（让脚本知道输入结束）
     
4. 执行
     边读 stdout 边限流（防内存打爆）
     边读 stderr 写审计日志
     超时 → SIGTERM（优雅，等待 flush）→ 宽限后 SIGKILL
     
5. 收尾
     累积 stdout 应用截断策略
     提取 stderr 尾部（失败时）
     扫描工作区变化 → 登记产物
```

超时终止**必须先 terminate 再 kill**：直接 kill 会让脚本来不及刷缓冲区，部分输出丢失。
（Windows 上 `TerminateProcess` 无优雅语义，等效硬杀，行为一致。）

## 4. 输出限流

边读边限流，防脚本打印数 GB 输出吃满内存。

| 策略 | |
|------|---|
| 逐行读取 | 用异步行迭代器，不一次读完 |
| 累计计数 | 边读边累积当前总字符数 |
| 达限停止 | 超过阈值立即停止读取，终止进程 |
| 保留原文 | 截断前写完整原文到审计日志 |

**为什么边读边限而不是读完再限**：等读完再判断时内存已被占满，进程可能已 OOM。边读边判可在达限瞬间止损。

## 5. 产物登记

脚本产出的文件在工作区内，需自动登记为可下载产物。

探测方式：执行前后扫描工作区，对比文件的 `(路径, mtime, size)` 三元组，新增或变化的即为产物。

| 产物字段 | 填充 |
|---------|------|
| 产物标识 | 随机生成，不可枚举 |
| 文件名 | 原始文件名 |
| 相对路径 | 相对工作区 |
| 媒体类型 | 按扩展名映射 |
| 大小 | 字节数 |
| 产出工具 | 脚本工具的限定名 |

前端下载时需校验请求者拥有该会话，防产物标识泄漏后被枚举。响应头必须设 `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`，防 HTML 产物被浏览器当页面执行。

## 6. 失败重试

只对特定失败类型自动重试，且**只有只读脚本可重试**。

| 情况 | 重试 | 理由 |
|------|:---:|------|
| 超时 | 只读脚本可，有副作用脚本不可 | 有写副作用重试会产生重复数据 |
| 进程启动失败 | 可，一次 | 可能临时资源不足 |
| 退出码非 0 | 不可 | 脚本逻辑问题，重试无意义 |
| 输出截断 | 不可 | 已达限额，重试仍超限 |

重试间隔需退避，防高频冲击宿主。

---

## 7. 依赖约束

- 脚本默认以平台所在解释器（`sys.executable`）运行，仅能用平台已装依赖。
- 重依赖场景：优先做成 MCP 服务；确需脚本时，把依赖加入平台依赖（`pyproject.toml`），**禁止**在脚本内 pip install 或捆绑运行时（网络与权限均不保证）。
- P1 示例：报告渲染类脚本需要 `jinja2` / `weasyprint` 时，已加入平台依赖（`pyproject.toml`）。

## 8. 自检清单

- [ ] 脚本以 `sys.executable` 宿主直跑，无 docker 调用
- [ ] 入参 JSON 单次写入 stdin 后关闭
- [ ] stdout 边读边限流，stderr 只写审计
- [ ] 失败时 stderr 尾部进模型上下文
- [ ] 超时先 terminate 再 kill
- [ ] 有写副作用的脚本不自动重试
- [ ] 产物标识不可枚举，下载需归属校验
- [ ] 响应头防 HTML 产物被当页面执行
- [ ] 对外开放脚本编辑前，重新评估轻量沙箱

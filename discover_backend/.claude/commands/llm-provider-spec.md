# LLM 接入与思考模式

## 适用场景 / 何时触发

- 实现模型客户端、流式解析、思考内容分离时
- 切换模型、新增模型提供方、调整思考强度时
- 排查流式中断、思考内容不显示、工具调用参数拼接错误时

---

## 1. 接入方式

**协议**：OpenAI 兼容规范（chat completions 风格）。

**传输**：httpx 异步客户端直连，流式请求。按 CLAUDE.md 技术栈约束，所有外部 HTTP 调用只走 httpx，不引入其他 HTTP 库，也不引入官方 SDK。

**目标模型**：qwen 3.7 max。模型标识、接入地址、密钥全部走配置与环境变量，代码中不出现字面量。

**为什么不用 SDK**：官方 SDK 会带入自己的重试、超时、连接池策略，与平台统一的降级与并发控制冲突；且思考内容字段属于提供方扩展，SDK 版本滞后时反而要绕过它。直连让流式解析与错误分类完全可控。

---

## 2. 提供方注册表

模型接入信息集中在配置文件，不散落在代码。

| 注册项 | 说明 |
|--------|------|
| 提供方标识 | 逻辑名，供智能体清单与平台配置引用 |
| 接入地址 | 兼容端点的基址 |
| 密钥环境变量名 | 只存变量名，不存值 |
| 模型标识 | 实际请求中的模型名 |
| 是否支持思考模式 | 决定是否发送思考相关参数 |
| 思考内容字段名 | 该提供方在流式分片中承载思考内容的字段名 |
| 是否支持工具调用 | 决定该提供方能否承载技能推理 |
| 上下文窗口 | 用于预算裁剪计算 |
| 默认超时与重试 | 可被平台配置覆盖 |

**思考内容字段名可配置**是关键设计。不同提供方承载思考内容的字段名不统一，把字段名做成配置项，换提供方只改配置不改解析代码。

---

## 3. 客户端职责边界

客户端**只负责**：构造请求、发起流式调用、解析分片、把分片归类为语义单元、分类错误。

客户端**不负责**：节流、打字机、事件编码、上下文裁剪、工具执行、重试策略决策。这些分别属于流式输出层、运行时层、工具层。

理由是单一职责：把节流塞进客户端会导致「换模型要重写打字机」这种荒谬耦合。

---

## 4. 流式分片语义分类

客户端把原始分片归类为几种语义单元，向上游输出统一的分片流：

| 语义单元 | 含义 | 上游处理 |
|---------|------|---------|
| 思考增量 | 模型的推理过程文本 | 走独立事件通道，前端分区渲染 |
| 正文增量 | 面向用户的回答文本 | 进打字机节流队列 |
| 工具调用增量 | 工具名与参数的分片 | 累积拼接，完整后交工具层 |
| 阶段切换 | 思考结束转正文、或转工具调用 | 触发前端分区切换 |
| 结束原因 | 正常结束、长度截断、工具调用、内容过滤 | 决定图的下一步 |
| 用量统计 | token 消耗 | 记入会话审计 |

**必须做语义分类而不是直接把原始分片透传**：原始分片格式随提供方变化，透传会让运行时层被迫理解提供方细节。

---

## 5. 思考模式

**开关与强度**由平台配置提供默认值，智能体清单可声明偏好，最终生效值为「智能体偏好优先，平台配置兜底」。

**思考内容处理原则**：

| 环节 | 规则 |
|------|------|
| 流出 | 走独立事件类型，不与正文混流 |
| 前端 | 独立分区渲染，默认可折叠 |
| 节流 | 可用与正文不同的节流参数（思考通常更长，可更快推送） |
| 回填历史 | **不把思考内容写回对话历史** |
| 审计 | 完整思考内容写会话日志，不进模型上下文 |

**不回填历史的理由**：思考内容体量大，累积几轮就会吃掉大部分上下文预算，而它对后续推理的边际价值远低于同等体量的工具结果。

**工具调用与思考并存**时，思考先流出、工具调用后发起。前端应在思考分区结束后再渲染工具卡片，顺序错乱会让用户困惑。

---

## 6. 工具调用分片拼接

工具调用的参数是**跨分片累积**的，不能收到一片就当完整参数解析。

拼接规则：
- 按分片携带的索引归组，同索引的参数片段顺序拼接
- 工具名通常只在首片出现，需缓存
- 拼接完成的判据是结束原因指示工具调用，而非「参数看起来像完整 JSON」
- 拼接结果解析失败 → 归类为参数错误，把错误摘要与该工具的参数说明一并回给模型，让它重试；不向上抛异常

**常见错误**：用「能否 JSON 解析成功」判断拼接是否完成。参数中途恰好构成合法 JSON 的情况真实存在，会导致截断的参数被当完整参数执行。

---

## 7. 请求构造

| 项 | 规则 |
|---|------|
| 系统消息 | 智能体全局约束 + 技能工作流 + 已加载的参考文档，合并为系统消息 |
| 历史消息 | 用户消息全保留；助手正文保留；工具结果按预算裁剪；思考内容不入历史 |
| 工具清单 | 由工具代理层提供当前暴露集合，客户端不自己决定 |
| 流式标志 | 恒为开启。平台不提供非流式对话路径 |
| 思考参数 | 按生效的开关与强度构造，提供方不支持则省略 |
| 温度等采样参数 | 走配置，不硬编码 |

---

## 8. 错误分类与重试

客户端把异常归类为几种，**不自行决定是否重试**，只把可重试性标记出来交上层。

| 分类 | 可重试 | 说明 |
|------|:---:|------|
| 连接失败、超时 | 是 | 网络层问题 |
| 限流 | 是 | 需按提供方返回的等待提示退避 |
| 服务端错误 | 是 | 有限次 |
| 鉴权失败 | 否 | 配置问题，重试无意义 |
| 请求非法 | 否 | 参数或上下文超限，需修正后再试 |
| 内容过滤 | 否 | 需调整输入 |
| 流中断 | 视情况 | 已产出部分内容时不可简单重试，会重复输出 |

**流中断是最需要谨慎的一类**：若已向前端推送了部分正文，重试会导致内容重复。处理方式是不重试、把已产出内容作为该轮结果、并向前端发出错误事件说明本轮不完整。

错误信息向上传递时必须脱敏：不含密钥、不含完整请求体。

---

## 9. 连接与超时

| 项 | 规则 |
|---|------|
| 客户端实例 | 进程级复用，不每次请求新建（新建会丢连接池，显著增加延迟） |
| 生命周期 | 随应用生命周期启停，按 CLAUDE.md 要求用类式异步上下文管理器实现 |
| 连接超时 | 独立于读超时配置 |
| 读超时 | 流式场景下指「分片间隔上限」，不是总时长上限 |
| 总时长上限 | 单独配置，防单轮无限拖长 |

**流式读超时容易配错**：若按总时长设读超时，长回答会被中途掐断；若不设分片间隔上限，上游卡死时会永久挂起。两者必须分开配置。

---

## 10. 自检清单

- [ ] 只用 httpx，未引入其他 HTTP 库或官方 SDK
- [ ] 模型标识、地址、密钥、采样参数全部走配置
- [ ] 思考内容字段名可配置，未硬编码
- [ ] 思考内容不回填对话历史
- [ ] 分片已做语义分类，未向上透传原始格式
- [ ] 工具调用参数按索引累积，完成判据不依赖 JSON 可解析性
- [ ] 客户端不做节流、不做事件编码
- [ ] 错误已分类且标记可重试性，未自行重试
- [ ] 流中断不简单重试
- [ ] 客户端进程级复用，生命周期类式管理
- [ ] 连接超时、分片间隔超时、总时长上限分别配置
- [ ] 错误信息已脱敏

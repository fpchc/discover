# Golden Cases（准确性回归用例）

> 用途：精简前后跑同一批用例，验证「准确性没有退化」。此文件是测试/QA 清单，不属于运行时契约，平台不加载。
> 目标：积累 20~50 个标准案例。每例包含输入 + 可断言的验证点。

## 验证点（所有用例通用，不依赖实时数据）

1. **输出形态**：可见回答是 200~450 字信息卡（多企输入时为多家各一张、全部输出），自然成文、非固定模版，企业定位 / 工商信息 / 主营业务等关键信息点齐全；缺项显式标注「未检索到」。
2. **排版达标（`card-format.md`）**：三段式结构齐全（加粗定位句 → 加粗小标签逐条的事实段 → 切入价值段）；注册资本 / 成立年份 / 人员规模 / 专利等大数字必加粗；风险（司法案件 / 失信等）以 `**注意**：…` 单列一行；电话 / 邮箱 / 官网逐条小标签列出；无整段纯散文、无 `|` / `｜` / `—` 机械串行模版。
3. **无编造**：每个字段三态之一——有来源 / 推断（显式标注）/ 未检索到（显式标注）；无空字段、无伪造数字。
4. **评分合规**：候选池场景下综合分来自 `score_calculator`，非手算；红线 / 信用<3.0 触发排除。
5. **推荐正确**：推荐 = 综合分第 1；推荐理由可追溯到证据（Score Trace 有 basis）。
6. **Final QA**：单企 2 问 / 候选池 4 问全过才出卡；证据不足的字段已降级标注。
7. **速度达标**：单企场景搜索 ≤2 轮且不评分；候选池场景召回 + 补搜共 ≤2 轮，评分与门禁脚本各调用 1 次。

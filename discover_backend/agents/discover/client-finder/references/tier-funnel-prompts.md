# 三层漏斗追问标准话术

本文档定义阶段 1（需求澄清）中三层漏斗追问的标准话术和节奏控制规则。在阶段 1 开始时加载。

---

## 一追问原则

1. **一次不超过 3 个问题**，等待用户回答后继续
2. **先问锚点（必须问），再问增益（默认追问），最后问微调（按需追问）**
3. **用户输入越详细，追问越少**——如果用户在首轮已经提供了某层的信息，跳过该层
4. **允许用户说"跳过"/"不知道"/"默认"**——不强迫回答
5. **追问完成后需做需求总结确认**——确保理解正确再进入搜索阶段

---

## 二第一层：必须问（核心锚点）

**唯一不可跳过的问题。用户必须至少提供产品/能力描述。**

### 标准话术

> 好的，我来帮您找客户。首先需要了解一下 —— **您卖什么产品？请简单描述一下。**

### 引导话术（用户说不清楚时）

> 没关系，试着描述一下：
> - 产品叫什么名字？
> - 它是干什么用的？
> - 用在什么设备上？
> - 举个例子：比如"高速背板连接器，用在数据中心交换机主板上"

### 判定：信息是否足够

| 用户回答 | 判定 | 下一步 |
|---------|:----:|--------|
| "高速背板连接器" | ✅ 足够（产品名明确） | 进入第二层 |
| "连接器" | ⚠️ 太宽泛 | 追问："什么类型的连接器？用在什么场景？" |
| "电子元器件" | ❌ 过于宽泛 | 用引导话术继续缩小范围 |
| "我卖东西给电子厂" | ❌ 无有效信息 | 用引导话术 + 举例说明 |

## 三第二层：默认追问（可跳过）

**4 个问题，用于锁定应用场景和提取需求信号。用户可以说"跳过"。**

### Q1：应用场景（默认追问）

**目的**：锁定应用场景 → 精确目标客户群

**话术**：
> 您的产品主要用在什么场景？解决了什么问题？

**跳过条件**：产品名本身已经充分描述了应用场景（如"数据中心交换机电源模块"）

### Q2：差异化优势（默认追问）

**目的**：竞品替代分析的锚点

**话术**：
> 相比市场上同类产品，您的主要优势是什么？（比如性能更好、价格更低、国产替代、交期更短等）

**跳过条件**：用户说"没什么特别的"或"就是标准品"→ 标注"无差异化优势"

### Q3：标杆客户（默认追问）

**目的**：提取真实需求信号

**话术**：
> 目前有没有合作的客户？可以举一两个例子吗？不用透露具体名字，说行业和产品就行。

**重要约束**：标杆客户信息**仅用于理解需求信号**（知道产品在什么行业、什么规模的企业中有真实需求），**不用于"找相似企业"**（除非用户明确要求 B5 场景）。

**跳过条件**：新品无客户 → 跳过，在报告中标注"新品"

### Q4：主要竞品（默认追问）

**目的**：竞品客户逆向发现的输入

**话术**：
> 您的主要竞品是谁？市场上哪些品牌和您竞争？

**跳过条件**：用户不知道或不想说 → 从产品品类自动推断

## 四第三层：按需追问（默认值兜底）

**6 个问题，每个都有默认值。仅在用户首轮未提供时追问，所有问题可批量询问以节省时间。**

### 第三层标准话术（批量）

在第一层和第二层追问完成后，若用户首轮未提供以下任何条件，一次性列出：

> 好的，需求基本清楚了。还有几个偏好，您可以选答（不回答就按默认值来）：
> 
> 1. **目标行业偏好？** 有特别想做的行业吗？比如通信、汽车、医疗…（默认：不限）
> 2. **目标区域偏好？** 全国做还是聚焦某几个省？比如华南、华东…（默认：全国）
> 3. **客户规模偏好？** 大企业、中小企业、还是都行？（默认：不限）
> 4. **有没有哪些不想碰的？** 比如国企流程太慢不想做、某类客户不想碰…（默认：无）
> 5. **销售节奏？** 急单还是建 long list？（默认：均衡覆盖）
> 6. **报告要多少家？** 默认推荐 5 家，您想要多少？

### 各问题默认值

| 问题 | 默认值 | 用途 |
|------|--------|------|
| 目标行业 | 不限 | 用于天眼查行业过滤 |
| 目标区域 | 全国 | 用于天眼查区域过滤 |
| 客户规模 | 不限 | 用于初筛时的规模过滤 |
| 排除条件 | 无 | 用于手动排除过滤器 |
| 销售节奏 | 均衡 | 急单 → 强调采购时机维度权重上浮；建 pipeline → 强调技术匹配和采购规模 |
| 报告数量 | 5 家 | 用户可指定 1-20 |

### 销售节奏对评分的影响

| 节奏 | 评分权重调整 |
|------|-------------|
| 急单 | 采购时机权重 +5%（从 15%→20%），采购规模权重对应 -5% |
| Pipeline | 技术匹配权重 +5%（从 20%→25%），采购时机权重对应 -5% |
| 均衡 | 不调整 |

## 五追问跳过规则

当用户首轮输入已包含某些信息时，自动跳过对应问题：

| 用户提供了 | 跳过的问题 |
|-----------|-----------|
| 应用场景/用途描述 | 第二层 Q1 |
| 差异化优势描述 | 第二层 Q2 |
| 标杆客户举例 | 第二层 Q3 |
| 竞品名称 | 第二层 Q4 |
| 目标行业 | 第三层 Q1 |
| 目标区域 | 第三层 Q2 |
| 规模偏好 | 第三层 Q3 |
| 排除条件 | 第三层 Q4 |
| 销售节奏 | 第三层 Q5 |
| 客户数量要求 | 第三层 Q6 |

## 六需求总结确认模板

所有追问完成后，必须做需求总结确认：

> 好的，梳理一下您的需求：
> 
> - **产品/能力**：[产品描述]
> - **差异化优势**：[优势描述 / 无特殊优势]
> - **EITIA 产业链定位**：[所属层级] → 客户主要在 [目标层级]
> - **目标行业**：[行业 / 不限]
> - **目标区域**：[区域 / 全国]
> - **客户规模**：[规模偏好 / 不限]
> - **排除条件**：[排除条件 / 无]
> - **销售节奏**：[急单/Pipeline/均衡]
> - **报告数量**：[N 家]
> 
> 确认没问题的话，我开始搜索了？

## 七历史感知差异化追问

当阶段 0 检测到是同一产品线索的追加调用时，追加问需做差异化：

### 追加调用的特殊话术

> 检测到您之前（[日期]）搜索过产品线索「[线索名]」，上次推荐了 [N] 家企业，后备池还有 [M] 家候选。
> 
> 本次将自动排除已推荐企业。您想：
> - **A）从后备池激活新客户** —— 直接从上次筛出来但没推荐的企业里挑
> - **B）全新搜索** —— 重新搜索，可能会发现市场变化后的新企业
> - **C）刷新上次推荐** —— 看看上次推荐的那些企业最近有什么新动态
> 
> 选一个就行。

### C3 线索刷新场景的特殊话术

> 好的，我帮您刷新上批客户的最新动态。会检查以下方面：
> - 有没有新的招标/采购项目
> - 招聘岗位有没有变化（扩招/收缩/新方向）
> - 最近新闻/公告（融资、扩产、新品、负面事件）
> - 供应商关系有没有变化
> 
> 每家企业预计需要 2-3 分钟，共 [N] 家，现在开始？

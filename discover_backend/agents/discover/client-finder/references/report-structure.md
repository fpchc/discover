# 客户发现报告结构（Markdown）

本文档是 `discover/client-finder` 最终交付物「完整 Markdown 客户发现报告」的唯一结构规范。最终交付为纯 Markdown 文字报告，不生成 HTML / PDF；`render` 阶段由平台确定性收尾，产出后平台执行 `gate_render_pass` 做阻断级结构校验。

## 一、必备要素（阻断级，缺一即判失败）

报告正文必须覆盖以下四个要素，否则 `gate_render_pass` 一票否决：

| 必备要素 | 内容要求 | 数据缺口处理 |
|---|---|---|
| **评分** | 候选池客户八维量化评分：各维分数、综合分、排名；红线一票否决 / 信用安全 < 3.0 的排除说明 | 缺数据维度取中性分并标注 |
| **决策人** | 关键决策人姓名 / 职位 / 联系方式 / 来源，决策链与触达路径 | 缺失标「未检索到」 |
| **切入策略** | 切入角度、话术要点、时间窗口、推进节奏、差异化优势 | 推断显式标注 |
| **风险** | 失信 / 被执行 / 经营异常 / 司法风险等风险点与规避建议 | 数据不足明说 |

> 以上四要素与 `AGENT.md` 的「报告须包含八维评分、决策人、切入策略、风险」一致，是 `gate_render_pass` 的最小阻断集合。

## 二、推荐章节骨架

按以下顺序组织 Markdown 章节；标题措辞可微调，但四要素必须覆盖：

1. **报告标题与摘要**：产品 / 目标场景 / 搜索范围 / 报告日期 / 数据截止日期 / 底部一句话结论。首句注明「数据来源受限版本：公开搜索」。
2. **候选池概览**：候选池 → 初筛 → 深挖 → 推荐，各级数量与漏斗关系；P1 候选池 ≥ 5 家即可，不足时向用户说明并继续。
3. **八维评分与排名**：综合分必须经 `score_calculator` 计算，禁止手算；给出每客户八维子分、综合分、排名与排除理由。
4. **客户深度档案**（每客户一节）：
   - 企业速览：全称 / 简称 / 标签 / 一句话定位
   - 匹配度诊断：八维得分与关键依据、亮点与风险
   - 采购规模估算：基数、公式、依据
   - 关键决策人：姓名 / 职位 / 触达路径 / 来源
   - 动态信号：时间、信号强度、来源
   - 切入策略：价值主张、切入路径、时间窗口、异议处理
   - 竞品替代分析：现有供应商、切换成本、差异化优势
   - 风险与注意事项
5. **附录**：
   - 数据采集日志（# / 时间 / 目标 / 维度 / 来源类型）
   - 评分方法论（公式 + 权重 + 红线规则）
   - 术语解释
   - 免责声明与使用建议

## 三、行文与数据纪律

- 数据缺口显式标注「未检索到」或「数据不充分·取中性分」，不得编造。
- 推断必须显式标注「推断 / 可能 / 估计」，禁止把猜测当事实。
- 关键结论标注来源或「推断」；单一来源的断言标注来源（如「据官网声称」）。
- 动态信号带日期，超 6 个月标注「可能已过时」。

## 四、门禁要求（render_pass）

`gate_render_pass` 对最终 Markdown 正文做以下阻断级校验：

1. **必备章节齐全**：正文必须同时出现「评分」「决策人」「切入」「风险」。
2. **无占位符**：不得出现 `XXX` / `TODO` / `TBD` / `占位` / `待补充` / `待填` / `placeholder`。
3. **无内部机制名泄露**：脚本名 / 模板名 / 门禁名 / 数据能力名不上屏（具体黑名单以 `gate_render_pass` 脚本为准）。

## 五、增量 / 追加模式

追加调用（持续跟进 / 竞品客户反推）时：

- 报告标题标注「新增客户」；
- 保留「上次推荐回顾」小结；
- 数据采集日志标注本次为增量采集。

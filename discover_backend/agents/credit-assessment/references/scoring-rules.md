# 客户账期评估 — 打分规则细则

> 本文件是 eitia-credit-assessment Skill 的**评分核心规范**。AI 逐维分析 → 填写原始分 + sub_scores + raw_data + source → `scripts/credit_calculator.py` 加权计算 → 输出综合授信分、授信等级、建议账期、建议额度。
> 评分必须可追溯：每维 ↔ sub_scores ↔ raw_data ↔ source 链路完整。

---

## 一、评分总体规则

### 1.1 评分流程

```
AI 逐维分析 → 填写原始分 + sub_scores + raw_data(≥80字) + source
    → credit_calculator.py 按 T1-T4 分层权重加权
    → 输出: composite_score + credit_grade + recommended_credit_days + credit_limit
```

### 1.2 通用约定

- **数据缺失**：子维度数据完全不可得 → 该子维度按满分的 50% 计（保守），标注 `partial_data: true`
- **维度完全缺失**：整个维度数据不可得 → 取中性分，标注 `score_neutral_reason`
- **非上市企业财务降级**：T2/T3/T4 非上市客户，F 维度的"盈利能力/现金流质量/增长势头"三个子维度**强制取中性分**（满分 50%），不因 AI 主观判断放宽——财报不可得是硬约束
- **风险排查（红线）**：不参与加权，5 条红线任一触发则阻断评分，综合分置 None

### 1.3 授信等级（表达"回款风险敞口"）

| 分数区间 | 等级 | 含义 | 授信决策建议 |
|------|:---:|------|------|
| 9.0-10.0 | **S 级 · 战略级** | 回款风险极低，行业标杆 | 建议签长约，授信系数 1.0 |
| 7.5-8.9 | **A 级 · 优选级** | 回款风险低 | 正常账期合作，授信系数 0.85 |
| 6.0-7.4 | **B 级 · 合格级** | 回款风险可控 | 有条件合作，缩短账期，授信系数 0.7 |
| 4.0-5.9 | **C 级 · 观察级** | 回款风险需关注 | 现金交易或短账期，授信系数 0.4 |
| < 4.0 或红线触发 | **D 级 · 高风险** | 不建议账期合作 | 现款现货/30% 预付，授信系数 0 |

> 与供应商评审的差异：授信等级表达的是**"放账期后的资金回收风险"**，不是供货质量。同一企业，作为供应商可能 S 级（供货质量高），作为客户可能 B 级（付款慢）。

## 二、T1-T4 客户类型分层权重

综合授信分 `CS = w1·F + w2·R + w3·S`，权重按客户类型切换。**这是本 Skill 与单因子信用评分的核心差异**——非上市客户财报缺失，财务权重必须下调，否则用不完整财务数据硬算会失真。

### 2.1 权重矩阵

| 客户类型 | 判定标准 | F 财务 | R 信用 | S 稳定 | 逻辑 |
|---|---|:---:|:---:|:---:|---|
| **T1 上市/大型** | 上市公司 或 营收 ≥ 5 亿 | 0.5 | 0.3 | 0.2 | 财报最硬，财务为主 |
| **T2 民营中型** | 非上市，营收 5000万-5亿 | 0.3 | 0.35 | 0.35 | 财务降权，信用+稳定升权 |
| **T3 贸易/小型** | 非上市，营收 < 5000万 或 贸易型 | 0.2 | 0.45 | 0.35 | 无财报，信用为王 |
| **T4 初创** | 成立 < 3 年 或 营收 < 1000万 | 0.2 | 0.35 | 0.45 | 稳定性最关键 |

### 2.2 层级判定流程

```
1. 是否为上市公司？（天眼查 search_listed_companies / Tushare stock_basic 确认）
   → 是 → T1
2. 营收规模？（上市：年报；非上市：企查查年报/天眼查摘要）
   → ≥5亿 → T1；5000万-5亿 → T2；<5000万 → T3
3. 成立年限 < 3 年 或 营收 < 1000万？
   → 是 → T4（覆盖 T2/T3）
4. 贸易型企业（无生产制造，纯购销）？
   → 是 → T3
```

### 2.3 非上市财务降级规则（硬约束）

T2/T3/T4 非上市客户，F 维度的以下三个子维度**强制取中性分**（满分 50%），无论 AI 是否通过其他渠道估到近似值：

| 子维度 | 满分 | 强制中性分 | 原因 |
|---|---|---|---|
| 盈利能力 | 2.5 | 1.25 | 无财报，毛利率/净利率不可得 |
| 现金流质量 | 2 | 1.0 | 无现金流量表 |
| 增长势头 | 1.5 | 0.75 | 无营收时序 |

非上市客户的**偿债能力**用"纳税评级 + 注册资本实缴"替代评分；**营运效率**如企查查年报披露应收周转可得则正常评分，否则取中性分。

## 三、F 财务健康（0-10，权重见 T1-T4）

**第一性原理**：这家客户有没有能力按时还钱？——盈利、偿债、现金流、成长、营运五维判断。

### 子维度评分锚定

| 子维度 | 满分 | 评分锚定（分档标准） | 数据源 |
|--------|:---:|----------------------|--------|
| **偿债能力** | 3 | 3=负债率<40% 且流动比>2；2=负债率40-60% 且流动比1-2；1=负债率60-80%；0=负债率>80% 或流动比<1 | 上市：Tushare `fina_indicator`（debt_to_assets / current_ratio）；非上市：纳税评级 A→3、B/C→2、D/无→1 |
| **盈利能力** | 2.5 | 2.5=毛利率>35% 且净利率>15%；2=毛利率25-35% 或净利率10-15%；1.5=毛利率15-25%；1=毛利率<15% 或亏损 | 上市：Tushare `fina_indicator`（grossprofit_margin / netprofit_margin）；非上市：强制中性 1.25 |
| **现金流质量** | 2 | 2=OCF/营收>0.15 且连续为正；1.5=0.05-0.15；1=0-0.05；0.5=OCF 为负 | 上市：Tushare `cashflow`（n_cashflow_act / revenue）；非上市：强制中性 1.0 |
| **增长势头** | 1.5 | 1.5=营收增速>30% 且净利增速>50%；1=15-30%；0.5=0-15%；0=负增长 | 上市：Tushare `fina_indicator`（or_yoy / netprofit_yoy）；非上市：强制中性 0.75 |
| **营运效率** | 1 | 1=应收周转≤90天；0.5=≤120天；0=＞120天 | 上市：Tushare `fina_indicator`（arturn_days）；非上市：企查查年报如可得，否则中性 0.5 |

**F 合计 = 偿债 + 盈利 + 现金流 + 增长 + 营运**（满分 10）

### 评分锚定（整体）

- 9-10 分：高增长 + 高盈利 + 低负债 + 强现金流，财务质量优异
- 6-8 分：财务稳健，个别指标中等但无硬伤
- 3-5 分：存在明显短板（高负债/负现金流/持续亏损）
- 0-2 分：财务严重恶化，有持续经营疑虑

### 关键提醒：现金流 vs 净利背离

若经营现金流与净利润严重背离（OCF/净利 < 0.3），即使盈利指标满分，现金流质量子维度也应**审慎下调**——这可能是利润含金量不足的信号。例：凯格 2026Q1 净利 6498 万但 OCF 仅 132 万，现金流质量从 1.5 审慎降至 1.0。

## 四、R 信用风险（0-10，权重见 T1-T4）

**第一性原理**：这家客户过去的付款记录干不干净？——不是"有没有风险"，而是"有没有欠款不还的黑历史"。

### 扣减项（基础 10 分，逐项扣减）

| 扣减项 | 每条扣分 | 规则 | 数据源 |
|--------|:---:|------|--------|
| **在册被执行** | 3 | ≥2 条直接归零（0 分） | 企查查 `get_company_risk_scan` + 天眼查司法维度（P0 双源） |
| **欠税/税务违法** | 2 | 每条 2 分 | 企查查 `get_tax_arrears_notice` / `get_tax_violation` |
| **票据违约** | 2 | 每条 2 分 | 企查查 `get_default_info` |
| **合同纠纷涉诉（作为被告）** | 0.5 | 上限扣 3 分 | 企查查 `get_judicial_documents`（筛选被告角色） |

**R = max(0, 10 − 被执行×3 − 欠税×2 − 票据违约×2 − min(被诉×0.5, 3))**

### 关键区分：原告 vs 被告

- 客户作为**原告**（追讨别人欠它的钱）→ 不扣分，反而是"应收管理严格"的正面信号
- 客户作为**被告**（被诉拖欠货款）→ 扣分，是"付款习惯差"的直接证据

例：凯格 14 条裁判文书全部为原告，R = 10 满分。

## 五、S 经营稳定性（0-10，权重见 T1-T4）

**第一性原理**：这家客户会不会在账期内突然出状况？——经营异常、股权、治理、合规、审计五类信号。

### 扣减项（基础 10 分，逐项扣减）

| 扣减项 | 每条扣分 | 数据源 |
|--------|:---:|--------|
| **经营异常（在册未移出）** | 5 | 企查查 `get_business_exception` |
| **股权冻结** | 3 | 企查查 `get_equity_freeze` |
| **实控人变更** | 2 | 天眼查变更记录 `get_change_records` |
| **高管异常**（处罚/失信） | 2 | 企查查 `qcc-executive` 组 |
| **行政处罚** | 2 | 企查查 `get_administrative_penalty` |
| **审计非标** | 5 | Tushare `fina_audit`（仅上市） |

**S = max(0, 10 − 经营异常×5 − 股权冻结×3 − 实控人变更×2 − 高管异常×2 − 行政处罚×2 − 审计非标×5)**

## 六、红线门禁（5 条二进制，不参与加权）

**第一性原理**：不是"风险有多大"，而是"有没有致命风险"。红线触发 → 综合分置 None，标"阻断/现金交易"，**不进入评分计算**。

| # | 红线项 | 判定标准 | 数据来源 |
|---|--------|------|------|
| 1 | 失信被执行人（在册） | `get_dishonest_info` 返回 > 0 | 企查查 + 天眼查双源 |
| 2 | 破产重整/吊销/注销 | 经营状态异常 | 天眼查 `get_company_basic_profile` |
| 3 | 严重违法失信 | `get_serious_violation` 返回 > 0 | 企查查 |
| 4 | 在册经营异常未移出 | `get_business_exception` 返回 > 0 | 企查查 |
| 5 | 连续 2 年经营现金流+净利双负 | OCF 和净利连续 2 年为负 | Tushare cashflow + income |

### 红线判定后行为

```
if 任一红线触发:
    status = "阻断"
    composite_score = None
    建议账期 = 0（现款现货/30%预付）
    授信额度 = 0
    → 报告仅输出已采集数据 + 红线标记，不进入评分
else:
    status = "通过" → 继续评分
```

## 七、账期档位与信用额度

### 7.1 账期档位（叠加 AR 硬约束）

| 条件 | 档位 |
|------|------|
| CS≥8.5 且 F≥8 | 90 天 |
| CS≥7 且 F≥6.5 | 60 天 |
| CS≥5.5 | 45 天 |
| CS≥4 | 30 天 |
| CS<4 | 现款现货/30% 预付 |

**硬约束**：`建议账期 = min(档位, 客户自身应收周转天数 AR)`——客户自己向别人收款都不到这个周期，我们垫资必超其回款节奏。

### 7.2 信用额度

`M = (PCB年盘子 P / 12) × 账期月数 × 授信系数`

- 月盘子 = PCB 年采购盘子 / 12
- 账期月数 = 建议账期天数 / 30
- 授信系数：S=1.0 / A=0.85 / B=0.7 / C=0.4 / D=0

### 7.3 PCB 需求盘子估算（见 demand-estimation.md）

额度计算的 P（PCB 年盘子）来自需求总体量摸排，三方法交叉估算给区间，**不给单点**。

## 八、AI 数据录入规范

### 8.1 每维必须附带的三要素

```json
{
  "tier": "T1",
  "f_scores": {
    "偿债能力": 3,
    "盈利能力": 2.5,
    "现金流质量": 1.0,
    "增长势头": 1.5,
    "营运效率": 1
  },
  "r_penalties": {"在册被执行": 0, "欠税/税务违法": 0, "票据违约": 0, "合同纠纷涉诉": 0},
  "s_penalties": {},
  "raw_data": "负债率39.68%、流动比2.14、毛利率41.26%、净利率16.29%、OCF/营收14.19%（但2024为负、2026Q1仅132万，审慎降现金流）、应收周转44天。……（≥80字）",
  "source": "上市公司公开财务数据、企业信用公开数据"
}
```

### 8.2 铁律

- `source` 字段**零工具名**泄露——用"上市公司公开财务数据"而非"Tushare fina_indicator"
- `raw_data` 必须 ≥ 80 字——包含具体数字、对比基准、采集日期
- AI 填完后传入 `credit_calculator.py` → 若脚本输出与 AI 估分偏差 > 0.5，以脚本为准
- **非上市企业**：必须显式标注 `tier` 为 T2/T3/T4，脚本自动执行财务降级

### 8.3 数据缺失处理

| 缺失类型 | 处理 | 标注 |
|------|------|------|
| 子维度数据不可得 | 该子维度按满分 50% 计 | `partial_data: true` |
| 整个维度数据不可得 | 维度取中性分 | `score_neutral_reason` |
| 非上市企业财务维度 | 盈利/现金流/增长强制中性分 | `非上市财报不可得` |

### 8.4 AI 自我检查清单（逐维填写时对照）

**F 财务健康**:
- [ ] 偿债能力有负债率 + 流动比两个数字（或非上市纳税评级）
- [ ] 盈利能力有毛利率 + 净利率（上市）或标注非上市中性分
- [ ] 现金流质量检查了 OCF/营收 + 是否连续为正 + 是否与净利背离
- [ ] 增长势头有营收增速 + 净利增速
- [ ] 营运效率有应收周转天数
- [ ] raw_data ≥ 80 字且含 ≥ 3 个具体数字

**R 信用风险**:
- [ ] 被执行记录双源确认（企查查 + 天眼查）
- [ ] 区分了原告 vs 被告（被告才扣分）
- [ ] 欠税/票据违约逐项排查

**S 经营稳定性**:
- [ ] 经营异常/股权冻结/行政处罚逐项排查
- [ ] 实控人变更/高管异常已检查
- [ ] 审计意见已确认（上市）

**全局**:
- [ ] 已判定客户类型 tier（T1/T2/T3/T4）
- [ ] 红线 5 条逐条检查
- [ ] `credit_calculator.py --test` 通过，脚本输出与 AI 估分偏差 ≤ 0.5
- [ ] source 字段无 MCP 工具名
- [ ] 无占位符残留（"XXX""待补充""推测#"）

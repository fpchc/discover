# 客户账期评估 — T1-T4 客户类型分层权重

> 本文件是打分规则中"权重切换"的完整规范。综合授信分 CS = w1·F + w2·R + w3·S，权重按客户类型自动切换。

---

## 一、为什么需要分层权重

不同客户类型的**数据可得性**天差地别：

- **上市公司**：财报强制披露，财务数据完整 → 财务健康 F 可以高权重
- **非上市民营中型**：财报不公开，仅纳税评级/工商数据 → 财务降权，信用+稳定升权
- **贸易/小型**：无生产、无财报、抗风险能力弱 → 信用风险 R 是唯一可靠信号
- **初创**：成立时间短，最怕经营不稳定 → 经营稳定性 S 最关键

**若统一用 0.5/0.3/0.2 权重**，非上市客户 F 维度用不完整数据硬算，会导致综合分失真——财务权重过高但数据却缺失。

---

## 二、权重矩阵

| 客户类型 | 判定标准 | F 财务 | R 信用 | S 稳定 |
|---|---|:---:|:---:|:---:|
| **T1 上市/大型** | 上市公司 或 营收 ≥ 5 亿 | 0.5 | 0.3 | 0.2 |
| **T2 民营中型** | 非上市，营收 5000万-5亿 | 0.3 | 0.35 | 0.35 |
| **T3 贸易/小型** | 非上市，营收 < 5000万 或 贸易型 | 0.2 | 0.45 | 0.35 |
| **T4 初创** | 成立 < 3 年 或 营收 < 1000万 | 0.2 | 0.35 | 0.45 |

权重加总 = 1.0（脚本已断言校验）。

---

## 三、层级判定流程

```
输入：客户完整登记名 + 上市状态 + 营收 + 成立年限

步骤 1：是否上市公司？
  天眼查 search_listed_companies / Tushare stock_basic 确认
  → 是 → T1（上市无论营收大小，财报可得，财务高权重合理）

步骤 2：营收规模？（上市：年报；非上市：企查查年报/天眼查摘要）
  → ≥5亿 → T1
  → 5000万-5亿 → T2
  → <5000万 → T3

步骤 3：是否初创？
  → 成立 < 3 年 或 营收 < 1000万 → T4（覆盖 T2/T3）

步骤 4：是否贸易型？
  → 无生产制造、纯购销 → T3（贸易企业无固定资产，信用风险更突出）
```

### 判定优先级

T1（上市）> T4（初创）> T3（贸易/小型）> T2（民营中型）

即：上市公司恒为 T1；初创（成立<3年）恒为 T4；贸易型企业降为 T3；其余按营收定 T2/T3。

---

## 四、非上市财务降级（配套硬约束）

T2/T3/T4 非上市客户，`credit_calculator.py` 自动执行以下 F 子维度降级：

| 子维度 | 满分 | 强制中性分 |
|---|---|---|
| 盈利能力 | 2.5 | 1.25 |
| 现金流质量 | 2 | 1.0 |
| 增长势头 | 1.5 | 0.75 |

偿债能力（纳税评级替代）和营运效率（企查查年报如可得）**不降级**，正常评分。

---

## 五、示例

### 凯格精机（T1 上市）
- tier = "T1"，权重 0.5/0.3/0.2
- F=9.0、R=10、S=10 → CS = 0.5×9.0 + 0.3×10 + 0.2×10 = **9.5 → S 级**

### 某非上市民营中型（T2）
- tier = "T2"，权重 0.3/0.35/0.35
- F 强制降级（盈利/现金流/增长取中性）后 F=7.0，R=10，S=10
- CS = 0.3×7.0 + 0.35×10 + 0.35×10 = **9.1 → S 级**（财务降权后仍高，因信用+稳定满分）

### 某非上市贸易小型（T3）
- tier = "T3"，权重 0.2/0.45/0.35
- F 降级后 F=6.0，R=8（有 1 条涉诉），S=8
- CS = 0.2×6.0 + 0.45×8 + 0.35×8 = **7.6 → A 级**（信用风险被放大，因贸易企业信用为王）
